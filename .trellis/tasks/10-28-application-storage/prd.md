# AI应用统一IndexedDB存储

状态：验收通过；证据见 verification.md，具体契约见 design.md。父任务：[存储与同步](../10-28-storage-sync/prd.md)。

## 目标

AI生成的小工具能够保存超过原限制的业务数据，采用统一清晰的存储接口和逻辑身份。用户已允许全新开发，不要求旧实例或旧持久格式兼容。

## 要求

- App与Applet使用独立应用命名空间或专仓；canonical instance ID稳定，不能与普通组件的裸ID删除路径冲突。
- 直接定义 App/Applet 新持久模型，不新增旧 localStorage 读取回退、迁移标志、双写或旧协议 ID 桥；新写入在事务确认后成功，失败可重试。
- 统一persist和tada.store的新接口契约，明确持久化失败与状态反馈，保持设置/业务状态分离。
- 重新制定并实测按UTF-8字节的应用预算；超过旧100000字符可保存，超过新预算明确拒绝，不能默默截断或承诺无限。
- 更新AI运行时说明、备份/同步、恢复和生命周期；同源连接在版本变化后失效重载。

## 验收

- [x] 两类应用包含中文/emoji且超过100000字符的数据写入→关闭→重开→刷新完整一致。
- [x] 新建、重复请求、写入中断与当前格式导入均无丢失/覆盖新值。
- [x] 取消挂载、卸载和撤销保持原数据保留语义；设置与切换运行形态不重置数据。
- [x] 新同步协议使用独立逻辑身份，App/Applet与组件同名ID互不干扰，不因物理存储路径产生重复或伪删除。
- [x] 真实浏览器quota失败、超预算、数据库不可用都有清晰反馈；未经确认的写入不显示保存成功。

## 范围外

不添加关系型查询API或任意SQL，不在此实现云端服务。
