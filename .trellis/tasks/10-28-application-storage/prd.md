# AI应用统一IndexedDB存储

状态：planning；行为范围已拆分，激活前补具体 design/implement。父任务：[存储与同步](../10-28-storage-sync/prd.md)。

## 目标

AI生成的小工具能够保存超过旧限制的业务数据，既有应用无需重写源码，数据和同步身份保留。

## 要求

- App与Applet使用独立应用命名空间或专仓；canonical instance ID稳定，不能与普通组件的裸ID删除路径冲突。
- 分别迁移fp.app和fp.applet，幂等、写入确认、读回校验和失败保留旧源；混合新旧设备通过v1逻辑ID适配。
- 保留persist和tada.store公开接口兼容性，明确持久化失败与状态反馈，保持设置/业务状态分离。
- 重新制定并实测按UTF-8字节的应用预算；超过旧100000字符可保存，超过新预算明确拒绝，不能默默截断或承诺无限。
- 更新AI运行时说明、备份/同步、恢复和生命周期；同源旧标签页在版本变化后重载提示。
- 旧同步记录 ID 兼容不代表旧客户端获得扩容能力；超过旧版限制的数据要求旧设备升级，兼容说明不得承诺旧版仍可编辑任意大值。

## 验收

- [ ] 两类应用包含中文/emoji且超过100000字符的数据写入→关闭→重开→刷新完整一致。
- [ ] 重复迁移、半途失败、IDB新值已存在、旧格式导入均无丢失/覆盖新值。
- [ ] 取消挂载、卸载和撤销保持原数据保留语义；设置与切换运行形态不重置数据。
- [ ] v1远端只看见原逻辑ID，不产生假墓碑或重复记录；旧设备在其容量范围内的写入可被新设备读取。扩容数据的旧版使用边界明确提示。
- [ ] 真实浏览器quota失败、超预算、数据库不可用都有清晰反馈；未经确认的写入不显示保存成功。

## 范围外

不添加关系型查询API或任意SQL，不在此实现云端服务。
