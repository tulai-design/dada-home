## 目标

用户可选择独立部署的共用服务同步不断增长的数据；搭搭和 aifenjing 各自接入，未部署或服务离线时仍完整本地使用。

## 要求

- 首期单人多设备：服务鉴权、命名空间、设备令牌撤销、持久卷；不开启不依赖服务，不建设公共注册平台。
- 服务独立于搭搭业务和部署，支持 application/space 隔离、通用版本对象与大内容；搭搭适配器和 aifenjing 适配器各自决定业务投影，服务不直接打开客户端 SQLite/Dexie 或解析聊天轮次。
- 持久变更队列、稳定mutation ID、服务端事务与单调游标；首次引导可分页，其后仅传增量，失败可重试且去重。
- 每记录版本检查，同记录冲突保留双方并可恢复，不同记录并集；拉取期间本地再编辑不能被覆盖。
- 墓碑与游标失效/设备退役方案明确，过期设备须重建基线；不要仅以90天回收制造删除复活。
- 保留客户端加密能力和密钥默认不同步策略；认证令牌和加密口令分离，有界对象和明细引用确认后发布。
- 提供服务配置入口、连接预检和关闭方式；HTTP整包provider与新服务协议是不同能力，明确识别版本，不解码旧快照格式。
- 交付独立接口与Docker部署资料、健康检查、备份/恢复；可与搭搭同机部署但不嵌入其公共取数代理，保持/__proxy原只读合同，PWA不缓存同步API。

## 验收

- [ ] 两个隔离浏览器连接本地临时服务，初次引导后新增一轮只发送变更，不重复历史；记录实际请求和字节。
- [ ] 丢响应后重试不重复，服务重启后数据和游标保持；拉取失败不跳过未应用数据。
- [ ] 离线两端新增均保留，同记录改动与删除/修改冲突可恢复；拉取期间新编辑保留。
- [ ] 无令牌/无权限请求被拒绝，撤销设备失效；口令错误不覆盖数据，密钥轮换中断可恢复。
- [ ] 关闭服务仍能编辑，恢复后同步；服务切换失败仍可本地使用，未经操作不删除其他快照。
- [ ] 镜像部署、持久卷备份恢复与代理/PWA路由集成验证通过。
- [ ] 两项目合成投影共用服务，同名 ID 在不同应用/空间隔离；共用鉴权、对象存储与版本接口，业务适配和冲突 UI 仍归各项目。

## 范围外

不新增公共账户、多人实时编辑、强制服务或第三方对象存储提供商。
