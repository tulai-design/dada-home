# 裁切与嵌套滚动复盘

## 1. 根因类别

- E（隐含假设）：把 CSS 的 `overflow:auto` 当成存在可用滚动路径。
- D（覆盖缺口）：只验证正常的局部滚动，没有同时验证滚动视口自身被外层裁切和祖先空白被裁的反例。

## 2. 两次局部修复为何不够

1. 遇到 auto/scroll 直接退出，漏掉没有实际滚动范围、整个视口被外层页面裁切的情况。
2. 将组件范围替换成整个滚动视口，虽然发现外层裁切，却把祖先下方空白被裁错误归给完整可见的小组件。
3. 最终按根到组件累计可访问区间：与裁切/滚动视口相交，仅按真实 scroll range 与当前 offset 扩展范围；原组件边界决定是否真的存在不可访问内容。

## 3. 预防机制

| 优先级 | 机制 | 已完成动作 |
| --- | --- | --- |
| P1 | 真实 DOM 回归 | 同一祖先内80px组件不报、600px组件真实裁切要报；200px局部滚动承载600px内容不报，scrollTop=350后仍不报 |
| P1 | 独立审查 | Spec轴用不同400×200场景复现，再次验证四个成对场景通过 |
| P2 | 规范 | 将可访问区间和成对用例要求写回前端质量规范 |

## 4. 系统性扩展

同类假设还可能出现在虚拟列表、抽屉内容与分栏布局中。当前任务只采页面组件外框，不擅自修改这些组件；未来增加采样目标时沿用同样的可访问区间验证。规则保持在采样器内，不在工具/App各自复制判断。
