# 存储与同步设计方向

状态：产品路线已确认；本文件是分期设计，不是已发布接口。日期：2026-10-28。

## 三层职责

1. 本地数据层：IndexedDB 保存业务数据和聊天，小型设备设置仍可保留 localStorage。统一失败语义、写入顺序、迁移、导出；本地成功不依赖网络。
2. 同步层：持久的变更队列与入站版本检查，分离逻辑记录身份和物理存储。v1 供应商继续走兼容整包；新服务采用游标增量。
3. 可选服务：首期单人多设备，独立同步 API + 持久卷；浏览器不开启服务时无强制请求。优先评估既有 Node 部署加轻量 SQLite，具体驱动、版本和镜像在服务子任务内核对，不先装依赖。

SQLite 存于服务所在机器的本地持久卷，由 HTTP 服务访问；不把 SQLite 文件放进 Gist/WebDAV 让多设备直接修改。其适用范围与来源见研究文档。

## 先修可靠性

`src/lib/db.ts` 当前读写失败返回 fallback，调用者无法区分空表和读取失败。新边界必须区分成功、不可用、读写失败，并携带可用于中文提示的原因。显式的无 IndexedDB 回落模式与已存在数据库发生错误是不同状态。

`componentData.ts` / `chat.ts` 的批次写入需串行协调：事务完成后才确认对应版本，失败保留待写项；较旧的 put/delete 批次不得覆盖较新输入。导出、同步等需要明确 flush 屏障，不能等待一个提前返回的并发 flush 就继续采样。UI 可以先显示内存改动，但不得等同于持久成功。

已有 `fp.chatTurns.v2` 聊天迁移在 IDB 不可用时仍可能删除唯一旧来源；第一阶段即修复，不能拖到应用扩容。组件迁移逐条处理坏数据，目标读取失败时保留来源，不覆盖可能存在的新值。

备份读入 `unknown`，完整校验版本、表、ID、值与可接受大小后再操作。IndexedDB 与 localStorage 不能共享原子事务；恢复须采用暂存/恢复日志等协议，覆盖中断后仍能回到原快照或完成目标快照。不得声称简单「先 clear 再 putMany」是原子恢复。

## 应用迁移与记录身份

- 旧位置是 `fp.app.<instanceId>` 和 `fp.applet.<instanceId>`，两类值形状不能混淆。新存储使用独立应用命名空间或专仓，不能直接借用普通组件的裸 ID；取消页面挂载当前会删除裸 ID 的组件数据。
- 从 canonical instance ID 定位业务数据；主题、容器、关闭窗口或最小化不改变 ID，不借迁移改变卸载保留行为。
- 迁移幂等：新值不存在才导入；写入并核验完成才登记迁移，失败保留旧来源。同源旧标签页识别存储版本并提示重载，不能声称旧代码会自动理解新库。
- v1 适配器继续用原 `ls:fp.app.<id>` / `ls:fp.applet.<id>` 逻辑记录 ID；出站不重复导出对应内部 kv，入站旧 ID 路由到新存储。避免搬库变成旧记录墓碑+新记录，兼容其他设备旧客户端。
- 统一写入/读取协议后再调整 Applet `persist`、App `tada.store` 的实现与 AI 说明，保留现有应用源码兼容性。容量按 UTF-8 字节统计，限额和浏览器 quota 分开；具体预算在该子任务用合成数据验证后设定。
- 逻辑 ID 兼容只保证记录映射，不给旧客户端扩容；新大值超出旧版限制时需提示升级旧设备，不承诺未升级设备仍可保存或编辑。

## 聊天增长

现有启动会加载所有会话元数据和当前会话的全部轮次；UI 最近 40 轮与模型历史预算并不能限制本地长期体积。

目标是会话索引、按页轮次与按需工具明细分离，明细以稳定引用关联；完整历史仍能导出和恢复。首批不删除历史、不用模型摘要替代唯一原文。调用模型时选择上下文独立于当前 UI 页，不能分页后只发屏幕可见消息。

减少重复大内容可评估内容寻址，但不得在缺少引用计数和删除/恢复设计时自动去重清理；它是后续优化，非首期分页的前置条件。

## v1 兼容边界

- Gist 已有 truncated → raw_url 支持，应补响应状态与实际读取边界，不重复实现或误称 1MB 为存储上限。
- HTTP/WebDAV 的条件写以服务真实支持为准；首次创建、已有 ETag 冲突、无 ETag 能力要分别测试。Gist 当前 PATCH 无可靠的比较并交换协议；重读校验不等于消除竞态，UI 不承诺多设备并发安全。
- 加密、是否同步密钥属于远端表示策略；即使业务哈希不变，策略变化也必须改写合格的新快照。关闭密钥同步要清理本次远端快照中的已知敏感字段；无法撤回 Gist 历史版本，不能宣称历史已擦除。
- 未知版本/坏密文/错误网络正文拒绝继续；读取失败不生成墓碑。保留错误上下文，重试按供应商反馈退避。
- full 入站先重查本地版本，不能覆盖 GET 期间新编辑；同非零毫秒冲突不能假报已最新。无设备确认协议时保守保留墓碑，不以 90 天作为删除安全证明；旧客户端原策略是兼容限制，升级新客户端不能修改旧设备代码。
- 不因新服务上线自动改变当前连接、同步范围或删除旧快照。

## 新服务协议要求（尚待子任务具体定稿）

| 边界 | 目标 |
| --- | --- |
| 身份与鉴权 | 单人命名空间、设备 ID、可撤销的同步令牌；不复用模型 API Key；无令牌时拒绝读取与写入 |
| 本地队列 | 每次本地持久变更有稳定 mutation ID；可在数据事务中写入的记录与 outbox 原子提交。仍在 localStorage 的同步配置须经带持久检查点的兼容桥发现，不能宣称跨库事务 |
| 推送 | 有界批次 + mutation ID 去重 + expected revision；服务在一个事务中写数据、递增游标并确认；重试沿用相同 mutation ID |
| 拉取 | 初次引导分批获取；以后按服务端单调游标读取变更；重连/过期游标走显式重建流程 |
| 入站 | 下载期间本地再次编辑时，按读取基线检查版本；不得直接覆盖新输入或错误推进游标，保留冲突版本 |
| 冲突 | 不同记录合并；同记录两端改动保留双方并提供可恢复选择，不以设备时钟静默决定输赢 |
| 删除 | 删除有版本和墓碑；过期设备重入先重建基线；墓碑清理依据设备确认/失效协议，不仅按固定天数删除 |
| 加密 | 保留客户端加密能力；按记录/有界对象封装，加密参数及格式版本明确。令牌用于访问控制，口令用于解密，两者分开；口令变更有可恢复迁移 |
| 容量与数据 | 服务验证信封/权限/字节限额；大明细拆成有界对象，确认所有引用可读后再发布记录；首期不新增附件上传 |

首期通过独立入口或独立进程接入现有部署；不放宽 `/__proxy` 的只读公共取数合同。同步路径绕过 SPA/PWA 缓存，持久卷、健康检查和备份恢复在交付时一起验证。接口定义与错误码、数据库 schema、认证初始化和部署参数均须在服务子任务 design 定稿，当前不得据此直接发布。

同步范围需按提供方能力定义：v1 按完整记录选择，不能通过删掉 turn.tools 字段来伪造「正文同步」。v2 若单独同步正文/明细，应记录明细是否存在、是否可获取及是否已下载；缺少明细不是删除，重新开启可补全，导出必须披露不完整范围。具体投影和引用模型在服务与管理子任务共同定稿。

## 性能与回退证据

用合成的 1000 个会话、单会话 10000 轮、带工具正文的大历史验证请求范围与内存加载边界；先测基线再规定耗时预算，不许伪造实测速度。关键断言是追加一轮的传输不随完整历史线性增长；首次引导和完整备份允许遍历所有数据。

新方案迁移先保留本地恢复点和旧远端快照，用户选择服务后才上传；校验成功再切换当前目标。服务不可用时保留本地 outbox；退回 v1 时按其可读体积边界导出，过大则明确说明，不能承诺任意大数据都可重新塞回 Gist。
