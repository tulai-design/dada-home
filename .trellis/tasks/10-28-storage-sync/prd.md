# 统一应用存储与可持续数据同步

日期：2026-10-28。本地可靠保存、可恢复备份、新快照同步与应用存储已交付；长期聊天与增量服务继续分期实施，父任务未完成。

## 问题与目标

原 AI 应用使用 localStorage 和 100000 JSON 字符限制，本轮已统一到独立 IndexedDB 应用仓和 8 MiB UTF-8 预算；聊天虽已使用 IndexedDB，但长期历史、工具明细及同步整包持续增长。用户希望继续存储工作，并确认「可以增加可选的自建同步服务，但仍支持纯本地使用」。

目标是先保证数据可靠保存和恢复，再让 AI 应用、长期聊天和多设备同步能够持续使用。2026-10-28 用户进一步要求同步服务可供 `aifenjing` 前端/桌面项目共用，先实施搭搭存储；服务不应绑定搭搭业务表。既有 AI 搭建父任务的 9 个子任务已交付，组合验收仍保留在原任务，不把本次研究视为其完成证据。

2026-10-28 后续授权更新：当前只有本人测试使用，存储与同步允许全新方案，无须旧实例/旧代码兼容；已归档工作记录保留事实，后续不再新增旧协议、旧数据迁移或双写。此授权不等同于自动清空真实数据或更改远端。

## 已确认范围

- R1 可靠保存：数据库或浏览器存储失败要可见、可重试；读取失败不得被当成真实空数据参与同步删除。备份必须包含已确认写入，损坏输入不得触发清库。
- R2 AI 应用存储：App 与 Applet 接入 IndexedDB，定义新存储模型，保持新模型内的应用实例身份、设置/业务数据分离以及关闭、取消挂载、卸载的数据保留语义。新容量策略按真实字节与浏览器可用空间解释，不能只放大原常量。
- R3 长期聊天：历史分页和工具大内容按需读取；模型上下文、界面渲染窗口与长期历史分别管理。未经用户主动操作，不截断或自动删除已有聊天。
- R4 快照同步：提供 Gist、WebDAV 和自建 HTTP 后端，使用严格的新快照协议，无旧格式解码；准确展示整包传输及供应商并发边界。Gist 为配置同步，排除 AI 聊天与应用业务状态，不自动删除其他同步文件；WebDAV 保留全部业务数据同步。S3 能承载全部数据，但本项目尚无 S3 适配器，不能把能力判断写成现有支持。
- R5 可选服务：纯本地是完整可用模式。设计可供搭搭和 aifenjing 共用的单人多设备自建同步服务，支持离线重试、分页拉取、去重与可恢复冲突。服务使用应用/空间隔离和通用对象/版本接口，业务模型、可同步字段、桌面路径和冲突呈现由各项目客户端适配。首期不要求用户注册账户，不建设多人实时协作。
- R6 可管理：按配置、应用业务数据、聊天、工具明细查看体积与状态，提供同步范围、导出和明确的清理入口。取消某类同步不等于删除云端或本地数据。

## 验收

- [x] A1 事务失败、quota、并发保存、快速切换会话与导出等行为可验证；失败不被报告为已保存，不生成伪删除。（R1）
- [x] A2 备份先校验后替换；导入中断可以恢复；新备份、应用存储和同步记录身份契约一致。（R1、R2、R4）
- [x] A3 中文及多字节应用数据超过原 100000 字符后可可靠保存/重开；真实超限明确失败；新数据写入中断重试无重复或丢失。（R2）
- [ ] A4 合成大历史启动/切换只取所需页，展开可读完整明细；上下文保持原语义，导出可还原全部数据。（R3）
- [x] A5 新快照协议的错误正文、未知版本、加密/密钥策略变化、限流与并发能力均有测试和真实状态提示。（R4）
- [ ] A6 自建服务初次全量引导后，新增一轮只传对应变更；重试不重复入库；两设备不同记录均保留，同记录冲突可恢复；服务关闭仍可编辑并稍后恢复同步。（R5）
- [ ] A6b 服务协议用搭搭及 aifenjing 合成数据适配验证；应用/空间隔离，同名业务 ID 不串数据，服务不依赖 conv/turn 或影视项目业务 schema。（R5）
- [ ] A7 同步范围切换不产生伪删除，容量单位准确；清理有范围预览，能导出；服务切换失败时本地仍可使用。（R6）
- [ ] A8 本地→备份恢复→快照同步→可选服务→两设备离线编辑完整组合验收通过，才归档父任务。

## 范围外

公开托管账户平台、多人实时协同/CRDT、强制联网或强制迁移、自建服务代管模型密钥、自动清空历史、附件上传产品、任意 SQL 工具、S3/R2/Supabase 等额外供应商首批实现。未来附件可预留独立对象边界，不在当前引入完整文件服务。
