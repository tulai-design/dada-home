# 统一应用存储与可持续数据同步

日期：2026-10-28。当前为研究与分期计划，尚未交付存储改造。

## 问题与目标

AI 应用仍使用 localStorage 和 100000 JSON 字符限制，聊天虽已使用 IndexedDB，但长期历史、工具明细及同步整包持续增长。用户希望继续存储工作，并确认「可以增加可选的自建同步服务，但仍支持纯本地使用」。

目标是先保证数据可靠保存和恢复，再让 AI 应用、长期聊天和多设备同步能够持续使用。既有 AI 搭建父任务的 9 个子任务已交付，组合验收仍保留在原任务，不把本次研究视为其完成证据。

## 已确认范围

- R1 可靠保存：数据库或浏览器存储失败要可见、可重试；读取失败不得被当成真实空数据参与同步删除。备份必须包含已确认写入，损坏输入不得触发清库。
- R2 AI 应用存储：App 与 Applet 接入 IndexedDB，迁移旧数据，保持应用实例身份、设置/业务数据分离以及关闭、取消挂载、卸载的数据保留语义。新容量策略按真实字节与浏览器可用空间解释，不能只放大原常量。
- R3 长期聊天：历史分页和工具大内容按需读取；模型上下文、界面渲染窗口与长期历史分别管理。未经用户主动操作，不截断或自动删除已有聊天。
- R4 既有同步：继续支持 Gist、WebDAV 和自建 HTTP v1，修复失败、加密策略与坏数据处理；准确展示整包传输及供应商并发边界。
- R5 可选服务：纯本地是完整可用模式。增加单人多设备的自建增量同步服务，支持离线重试、分页拉取、去重与可恢复冲突。首期不要求用户注册账户，不建设多人实时协作。
- R6 可管理：按配置、应用业务数据、聊天、工具明细查看体积与状态，提供同步范围、导出和明确的清理入口。取消某类同步不等于删除云端或本地数据。

## 验收

- [ ] A1 事务失败、quota、并发保存、快速切换会话与导出等行为可验证；失败不被报告为已保存，不生成伪删除。（R1）
- [ ] A2 备份先校验后替换；导入中断可以恢复；旧备份、旧应用数据和旧同步记录身份均兼容。（R1、R2、R4）
- [ ] A3 中文及多字节应用数据超过旧 100000 字符后可可靠保存/重开；真实超限明确失败；旧数据迁移中断重试无重复或丢失。（R2）
- [ ] A4 合成大历史启动/切换只取所需页，展开可读完整明细；上下文保持原语义，导出可还原全部数据。（R3）
- [ ] A5 v1 的错误正文、未知版本、加密/密钥策略变化、限流与并发能力均有测试和真实状态提示。（R4）
- [ ] A6 自建服务初次全量引导后，新增一轮只传对应变更；重试不重复入库；两设备不同记录均保留，同记录冲突可恢复；服务关闭仍可编辑并稍后恢复同步。（R5）
- [ ] A7 同步范围切换不产生伪删除，容量单位准确；清理有范围预览，能导出；新旧方案迁移失败可退回旧路径。（R6）
- [ ] A8 本地→备份恢复→旧同步→可选服务→两设备离线编辑完整组合验收通过，才归档父任务。

## 范围外

公开托管账户平台、多人实时协同/CRDT、强制联网或强制迁移、自建服务代管模型密钥、自动清空历史、附件上传产品、任意 SQL 工具、S3/R2/Supabase 等额外供应商首批实现。未来附件可预留独立对象边界，不在当前引入完整文件服务。
