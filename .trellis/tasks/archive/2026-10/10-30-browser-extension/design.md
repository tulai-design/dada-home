# 技术设计

## 变更边界

当前仅有独立书签桥；完整 React/PWA 运行于站点。新增共享应用的本地扩展构建与平台适配，保留现有领域协议、渲染、存储和纯操作。

## 模块所有权

- 构建/浏览器接入：Vite、package scripts、新扩展资源、平台类型与判断、网络授权与原生书签适配。构建输出 `dist-extension/`，下载文件 `public/dada-extension.zip`，现有书签桥 ZIP 单独保留。
- 沙盒：App/Applet iframe 接入共享扩展沙盒 bootstrap，保留 Web srcdoc 路径。沙盒页位于 `browser-extension/sandbox.html` 与 `sandbox.js`，builder 原样复制。会话和消息来源必须与 iframe 绑定；嵌套运行时需转发不能赋予扩展 API。
- 主会话：扩展启动/跨实例协调、下载入口、文档、集成。启动持有同源 Web Lock 才初始化完整应用；等待实例显示可达的继续使用/接续入口。关闭前有待保存或保存故障时触发浏览器离开提示并尽力执行保存屏障；不把异步 unload 当成可保证完成的事务。锁随文档销毁释放，接续页才首次建立业务缓存；无锁时不静默编辑。用户确认强关、系统终止等仍不能保证未完成的异步写入。

## 平台合同

- `src/lib/platform.ts` 提供 `isExtension(): boolean` 与最小 Chrome API 类型；通过真实扩展协议/runtime 身份判断，不依赖 DEV 标志。
- 扩展构建 mode 为 `extension`；显式排除 PWA 与 analytics，公共下载 ZIP 不复制进扩展，避免递归包。
- 网络 fetch 在扩展入口安装适配器，包内相对资源保持原样；HTTP(S) 按可选主机权限请求。等待权限队列使用 UI 用户手势批准，支持 AbortSignal 与拒绝。内置 `/__proxy?url=` 在扩展中解析成直接目标；用户明确指定的远端代理仍受权限控制。
- 书签桥后台为新扩展入口复用 handlers，优先验证同扩展可信发送者；网页桥保留其已授权站点检查。
- 普通扩展页仅运行随包代码；动态应用放 manifest sandbox 独立页。对 App/Applet 已有 postMessage 协议保持兼容，具体执行文档仍使用其原 CSP，元协议不能变成任意宿主 API。
- 单实例不是把普通内置功能变成只读阉割版。首个页面完整运行；其他入口说明已打开并可定位该页面，接续在旧实例清理保存后进行。用户可在任意新标签页进入现有完整实例，不复制应用或数据。

## 数据与回滚

网页与扩展 origin 独立，不自动读取用户现有站点数据。沿用 JSON 备份和显式同步；保持稳定扩展标识。Web 构建继续可用；移除扩展构建不要求修改领域数据。所有浏览器验证使用隔离配置目录及合成凭据。

## 风险验证

优先实测 manifest sandbox 中动态模块与父页 CSP、隔离下的 SDK 协议、跨页面锁和保存接续。扩展安装的真实限制与外部服务网络不可达需在验收中如实区分；不以加载页面成功代表完整功能验证。
