# Agent 取消与工具失败语义修复（A1/A2）

## 目标与授权

用户明确要求按架构评估顺序先实施 A1/A2。本轮交付可观察的执行正确性修复、必要行为回归和真实 UI 验证，在 main 本地提交，不推送或发布。项目工作流优先，已确认方案不重复询问。

## 背景

2026-10-30 在基线 bd9fcc4 重新运行归档探针：审批等待时 abort 后仍挂起，迟到同意仍执行一次模拟写；WorkspaceError 被 guard 转为普通字符串，dispatchTool 仍记录 ok:true。报告见 docs/work/research/2026-10-29-architecture-extensibility-audit.md。

## 需求

- R1：停止应结束待决审批并完成该轮取消清理；旧审批答复不能执行工具、写入永久授权或影响下一轮。取消前后不发送下一次模型请求或开启同批后续工具。
- R2：模型请求和工具执行统一传播 AbortSignal。预先取消、请求期间、审批前后、同批工具之间都检查。已提交副作用保留；运行中的异步工具合作取消，不能假装回滚，不以提前释放锁允许旧写与新轮并发。
- R3：工具参数失败、领域拒绝、用户拒绝、未知执行异常均是失败事件；成功保持成功。领域异常不能先变成成功文本，也不通过中文关键词推断状态。模型仍获得可解释结果并能继续纠正；取消单独终止执行，不当作普通工具失败继续循环。
- R4：检查主工具与站点/生活/搜索等现有工具目录，去掉同类吞错问题；直接 execute/runTool 的既有错误合同随行为回归同步更新。正常空结果/信息性回复不得机械改为失败。
- R5：聊天保持 convId/turnId 归属、发送锁、历史保存和现有审批体验。取消标识、忙碌状态和待决卡片正确清理，可开始下一轮；迟到输出不能污染已结束轮或其他会话。

## 验收

- AC1：隔离行为覆盖取消前请求、待决审批停止、取消后旧同意/总是允许、同批工具间停止、模型流取消与协作工具取消；无额外请求/执行/永久授权，监听与发送锁清理。
- AC2：真实工具至少覆盖工作空间领域失败及站点/生活/搜索错误，工具事件/聊天痕迹为失败；参数、拒绝和未知异常分别验证，成功与失败文本语义不靠字符串前缀判断。
- AC3：真实独立浏览器使用合成模型响应触发审批与停止，卡片/忙碌状态/取消记录正确，旧审批不能提交，下一轮可发送；实际领域失败事件和聊天显示一致。无真实模型、用户数据或凭据。
- AC4：本机 pnpm 类型检查、完整 test、build，通过必要 OpenAI/Anthropic 协议回归。项目无 lint 命令。
- AC5：规范与运行时合同记录真实交付行为，原评估保留日期并注明 A1/A2 已修复及证据；验证、双轴审查、提交归档日志完成。

## 范围外

不实现 A3-A7、不添加多 Agent、后台执行、插件协议，不升级独立 agent 包、不改浏览器扩展多开策略，不清除真实数据。未来执行身份设计不在本轮引入。
