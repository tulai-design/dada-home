# 可靠本地写入与可恢复备份

状态：completed；实现、双轴审查与质量门禁已通过，见 verification.md。父任务：[存储与同步](../../../10-28-storage-sync/prd.md)。

## 目标

已确认写入的数据刷新后可读；容量不足和事务失败可见并可重试，备份替换中断后能恢复原数据。

## 要求

- 区分数据库不可用、读取失败与真实空值；成功返回以事务完成为准。为配置回落写入补失败反馈，不能只更新内存就宣称保存成功。
- 组件与聊天保存队列串行化并保留失败批次；旧 put/delete 不得晚于新值生效。导出与同步共用等待所有先行写入完成的屏障。
- 备份结构、版本、ID、值类型和大小先校验；替换过程可恢复，跨 localStorage/IndexedDB 的恢复过程不能虚称单一原子事务。
- 数据库读取或 flush 失败时同步停止，不写远端、不生成墓碑；保持旧正常数据与现有公开调用方式。
- 旧聊天和组件迁移只有在目标事务完成且核验后才能清除来源；数据库不可用、读失败和单条坏 JSON 不能导致删除唯一旧记录或中断其他合法迁移。

## 验收

- [x] 故障注入 quota/事务 abort 后有失败状态，待写数据仍能重试；刷新恢复最终成功值。
- [x] put/delete 交错、重入 flush、会话快速切换不会丢失或恢复旧值；真实 IndexedDB 隔离浏览器验证通过。
- [x] 编辑后立即导出包含该次已确认更改；导出过程中写入按明确快照边界处理，失败不得下载伪完整备份。
- [x] indexedDB:true、未知版本、缺失表/坏行拒绝恢复且原数据不变；合法旧格式可导入，恢复中断可继续或回退。
- [x] 读取故障时运行同步，模拟 fetch 断言零远端写入和零新增删除墓碑。
- [x] 无 IndexedDB 或事务失败时 `fp.chatTurns.v2` 保留；组件迁移遇单条坏 JSON 后其他合法记录仍可访问；恢复后幂等迁移。

## 范围外

不改变应用存储位置或配额，不改变同步格式，不部署服务。
