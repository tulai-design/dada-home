# AI 页面搭建能力增强

批准日期：2026-10-27。状态由 task.json 管理；本文件不是功能完成声明。

## Problem Statement

用户要求 AI 改造首页或开发工具时，已有工具能完成配置和源码写入，但成品仍会出现风格不一致、特效喧宾夺主、窄容器体验不稳定和功能积木不足。AI 看不到实际渲染，配置成功不能证明页面好用。项目也缺少可持续维护的任务与文档体系。

## Solution

先建立 Trellis 任务与 Matt 技能工作流；统一设计指引，将特效约束变成目录与运行时能力，并提供真实页面检查。随后完善响应式布局和可预览的首页组合，扩展已有简单图表/表格为实用的数据工具能力。

## User Stories

1. 作为开发者，我希望新会话能恢复需求、规范、依赖和进度，避免反复从聊天推断。
2. 作为用户，我希望工具示例与默认主题一致，避免 AI 反复生成大圆角、重阴影和冗余文案。
3. 作为用户，我希望 AI 根据内容主次选择特效，而非默认堆叠装饰。
4. 作为手机用户，我希望内容与交互按实际容器适配，触屏不依赖悬停。
5. 作为分栏用户，我希望缩小页面后布局仍可用，业务状态不被重置。
6. 作为用户，我希望浅深主题切换后特效和文字始终可读。
7. 作为减少动画的用户，我希望静态结果完整表达内容。
8. 作为用户，我希望特效失败时标题、正文和功能仍然可用。
9. 作为用户，我希望 AI 改完后获取真实测量，区分通过、失败和无法测量。
10. 作为用户，我希望从合适的首页方向开始，保留自己的应用、数据与快捷入口。
11. 作为用户，我希望先看草稿，再整体应用、取消或撤销改版。
12. 作为工具使用者，我希望 AI 能制作可读的趋势图和可筛选的记录列表。
13. 作为维护者，我希望新增库经过宿主封装、来源记录与兼容验证，避免产物各自维护一套 UI。

## Implementation Decisions

- Trellis 是唯一任务系统；Matt 方法用于需求归纳、纵向任务、行为测试和双轴审查。
- 内置/声明式组件、特效目录、Lobe Applet 和 HTML App 的现有分工保留。
- AI 通过受控目录使用新 UI 能力；计算逻辑导入与 UI 组件导入区分。
- 扩展现有工作空间操作、模板和撤销机制，兼容旧配置与应用标识。
- 特效按同页组合处理，统一主题与静态替代；历史 vendor 来源按实际版本核对。
- 检查工具先做确定性测量；截图、多模态模型和审美评分不冒充当前能力。
- 后续复杂任务激活前完成其技术设计，选库不得混用不同版本文档。

## Testing Decisions

测试公开行为而非源码字面值。优先复用现有工具/工作空间/应用协议入口；渲染相关规则通过真实 DOM/组件行为验证。重要基准覆盖 320、375、768 和桌面容器、AI 分栏、两种主题、减少动画、失败与恢复。没有运行过的组合记为未验证。纯规范文案不添加镜像快照。

## Acceptance

- [ ] 所有必要子任务有独立验收记录，父任务完成集成审查。
- [ ] AI 首页改造可完成生成、实测检查、修正、草稿应用与撤销。
- [ ] 特效组合、主题切换、静态降级与容器变化不会丢失关键内容或业务状态。
- [ ] 新图表/数据管理能力可由 AI 发现和调用，并在窄容器正常使用。
- [ ] 文档始终区分已有能力与目标能力，任务状态与证据一致。

## Out of Scope

任意 npm UI 导入、整套视觉库迁移、默认 3D、全站滚动接管、公开站点发布、跨域内容截图、后端账户/数据库扩展。Magic UI、Embla、dotLottie 为后续候选，确定具体使用场景后另建纵向任务，当前不安装。
