# 可靠保存与备份设计

日期：2026-10-28。用户授权先推进本地存储；通用同步服务是后续独立产品边界，本子任务不部署服务、不改变同步范围。

## 最小行为差距与职责

真实差距是落盘失败会被当成功、旧队列可覆盖新值、迁移和恢复可删除唯一数据。职责位于 db/业务存储/备份边界，不能仅在设置页捕获错误。

- `db.ts`：严格区分不可用与事务失败；请求成功后还需等待事务 complete；增加同步入队的多仓 batch 和一致 snapshot。数据库升级新增独立 recovery 仓，不加入业务导出/同步。
- `componentData.ts` / `chat.ts`：串行版本化队列；flush 等待调用前的工作，失败保留并能重试；聊天待写快照绑定原 convId，快速切换不把旧轮次盖章到新会话。迁移确认并读回后再清来源。
- `persistence.ts`：本机持久化错误与重试注册、恢复期间写入门禁。同步返回成功仍由原实现负责，本模块不宣称联网状态。
- `store.ts` / `workspaceStore.ts`：保留即时内存交互，但同步保存失败登记可见状态和可重试最新值；导出与同步在持久化失败时中止。App/Applet 容量和存储位置暂不变化。
- `storage.ts`：所有输入先校验；导出前保存屏障；恢复使用多仓事务和 recovery 日志，支持跨 localStorage/IDB 的中断恢复。
- 宿主启动与可见错误：启动失败也能显示错误和重试，不渲染空白或静默进入可编辑默认库；设置页导出捕获错误，宿主展示紧凑保存错误与重试入口。

## 数据库内部接口

保留现有 `db.get/all/byIndex/put/putMany/del/delMany/clear` 名称，改成失败 reject，不再 fallback。`openDb()` 只在 API 不存在时返回 null；打开/blocked/事务错误可观察并允许后续重试，versionchange 清连接缓存。

新增 `db.batch(operations)`，操作为 `{store,type:'put',value}` / `{store,type:'delete',key}` / `{store,type:'clear'}`，相关 store 放同一 readwrite 事务，全部请求同步排入。新增 `db.snapshot()` 在同一 readonly 事务读取 kv、convs、turns。恢复仓为 `recovery`，keyPath `k`；它不属于业务数据与 v1 同步扫描范围。

## 队列和导出

每键保存最新 revision 与待写操作，串行批次执行；只确认本批对应 revision，失败保留该项且不把新值回退旧快照。多仓聊天元数据/轮次使用 batch。后台 timer/pagehide 的 reject 有处理，用户可见错误保留。

导出先等待组件/聊天队列与配置重试屏障，再读取 IDB 一致快照及 localStorage 配置，保证调用前接受的更改已落盘。导出不持有写入门禁，流式回答可以继续；期间的新更改可能进入当前或下一次快照，不宣称两个引擎具有同一原子时间点。未保存的更改要先重试成功，否则导出失败，不生成缺少最新数据的成功文件。恢复先等待已开始的同步结束，再通过独占门禁阻止同标签页新写并排空旧队列；生成中不允许确认替换。同步运行等待相同持久化屏障；数据库读取失败自然 reject，不能生成墓碑。

## 可恢复替换

支持现有无版本备份，新备份增加显式版本标识。校验 JSON 对象、已知格式版本、配置字符串和值、kv/convs/turns 行形状、重复 ID、轮次关联和大小，保留兼容扩展字段但不信任类型断言。缺失/未知/损坏拒绝，空的合法新快照可以显式恢复。

恢复在独立 recovery 仓记录原业务 snapshot 和原 fp.* 配置；同一个 IDB 多仓事务同时写入恢复日志并替换业务仓。之后替换 localStorage，全部完成才删除日志并重载。如果 localStorage 或后续步骤失败，按日志恢复旧 IDB 和配置；回退也失败时保留日志并显示恢复错误。启动在任何业务初始化/同步前检查日志并完成回退。崩溃后回到原状态或完成目标都满足可恢复语义，不谎称跨两个存储引擎原子提交。

恢复期间同标签页写入被阻止，排队工作必须先完成；旧异步批次不能在恢复后重新写入。恢复回退也失败时 `backup-restore` 状态持续阻止业务写；仅 `withPersistenceExclusive(..., {recovering: true})` 允许专用恢复入口重试，它仍不允许并发独占。恢复/启动以同源 Web Lock 串行执行，等待活跃恢复完成后再读日志；没有 Web Locks 时不执行危险替换或日志恢复，普通无日志启动仍可用。已打开的其他标签页没有业务写隔离保证，UI 明确要求先关闭其他搭搭标签页。

## 检查边界

使用现有公开 `readData/writeData/flush`、chat store、parse/import/export、runSync 的行为入口。Node 隔离夹具做故障与交错；真实 IndexedDB 在全新浏览器 context 中做 batch abort、重载、升级、备份/回退及 quota 注入。不能使用真实用户存储或同步。

不做 AI 应用搬库/扩容、聊天分页、Gist 范围切换或共享服务实现；这些保持后续子任务。没有引入新的外部依赖。
