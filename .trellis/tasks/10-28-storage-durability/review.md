# 双轴审查

基线：`7991440`。范围：本轮工作区 diff 和未跟踪实现/测试；未使用用户存储或真实远端。Standards 由独立浏览器/研究代理审查，Spec 由核心与备份代理交叉审查未由自己实现的模块，主会话检查跨层集成。

## Standards

- 旧聊天只检查部分字段并断言 Turn，重复 ID 会覆盖后清除唯一来源。真实 Chromium 以不完整行及两个同 ID 不同正文记录复现。修复为完整旧轮次验证、非空唯一 ID；失败保留原文，启动提供原始配置救援。
- 恢复错误持续门禁会挡住恢复入口本身。修复为仅恢复入口可使用的 `recovering` 选项，业务写仍拒绝，嵌套恢复仍拒绝；覆盖同页权限恢复后重新读取。
- 错误标题按阻断状态而正文取第一条，先到的旧数据警告会遮住保存失败。修复为恢复错误、阻断错误、普通警告的显示优先级。

## Spec

- 工作空间读取重试不能在失败时发布默认状态，也不能重新捕获版本基线而覆盖期间的用户编辑。已覆盖连续读失败、期间保存也失败、最后权限恢复的完整序列，确认最终落盘为最新编辑。
- 恢复回退再次失败后必须继续阻止编辑，否则下次回退会丢掉之后的新修改。已补持续业务门禁及真实 App 的 inert、重新加载入口和恢复重试。
- 备份输入还包括旧 `fp.chatTurns.v2` 与工作空间配置。不能只验证它们是 JSON 字符串后清库，重启才发现不能迁移。复用旧轮次验证；对工作空间做至少含一页可迁移页面的最小预检。其他设置仍有各自的领域规整，不宣称所有业务配置已完整语义校验。
- HTML App 的桥接 `set` 直接写 localStorage，会绕过其他存储入口的恢复门禁。已将它接入同一门禁，以真实 AppBlock 消息入口验证恢复期间与回退失败后后台请求返回错误且原值不变，恢复后可写；保留原存储位置、容量和权限。

## 保留的边界

- 恢复/启动检查以 Web Locks 协调；已打开的其他标签页业务写未自动隔离，确认文案要求先关闭其他搭搭标签页。
- 导出先等待保存屏障，流式片段仍可继续；不宣称两个引擎具有共同原子时间点。
- 损坏旧配置原样导出用于救援，严格导入仍会拒绝它；启动页原始配置救援不包含数据库聊天。
- 本轮不修改 Gist 范围、v1 并发合并协议、AI 应用 100000 字符配额、聊天分页或共用服务实现。

最终质量门禁与可复用入口见 verification.md。
