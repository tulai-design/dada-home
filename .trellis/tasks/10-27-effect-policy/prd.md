# 约束页面特效组合与运行质量

父任务：`10-27-ai-builder`。批准来源：2026-10-27 用户确认三批增强方向并要求建立 Trellis/Matt 工作流。

## 用户问题与交付行为

用户让 AI 增加背景或效果块时，AI 能知道移动适配和运行成本，宿主对同页组合执行一致规则，并清楚说明拒绝或降级原因。

## Blocked by

`10-27-builder-guidance`

## 验收标准

- [ ] 每个效果有可查询的渲染类型、适用容器、触屏/减少动画处理、质量上限及来源信息；未知来源明确标记待核对。
- [ ] 图层与内容块共同计预算，添加、更新、模板应用及已存配置加载不出现绕过或静默损坏。
- [ ] 对现有超预算页面采取可恢复的兼容策略，不删除配置；用户能理解限制或静态降级。
- [ ] 沿用并补齐现有离屏/隐藏暂停、质量限制和资源清理，不因封装重复运行渲染循环。
- [ ] 通过公开工具/工作空间行为测试和窄容器、减少动画下的真实组件验证。

## 测试决策

工具写入到工作空间的公开入口验证组合和兼容；渲染层验证真实暂停与静态策略。先选一个代表效果贯通，再扩目录。

## 范围外

不引入整套外部 UI 库、不默认开启 3D；未查明的历史源码许可不擅自改写为新许可。

## 计划状态

本 PRD 固定用户行为和边界；复杂任务在 start 前补齐 design.md、implement.md，并核对依赖及接口。当前不表示实现已开始。
