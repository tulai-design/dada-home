# 跨层数据流检查

先画出本次字段/行为实际经过的链路，再选择验证入口。常见链路如下：

- AI 配置：工具 schema/parse → 领域操作 → store commit → 渲染 → 撤销/重做。
- 导入配置：备份/模板 → migrate/normalize → store → 渲染。
- 特效：目录 → 参数规整 → 页面图层或内容块 → views → vendor 生命周期。
- Applet：源码 → 沙盒逻辑 → 积木消息 → 宿主渲染 → 事件回传；设置/尺寸变化走各自消息。
- 取数：页面/工具 → 代理模板 → 开发或生产代理 → 上游 → 解析与错误状态。

修改完成前检查：

1. 新字段是否同时覆盖写入、读取/迁移、复制/模板和展示？缺失值与显式清空是否保持区别？
2. 用户操作和 AI 工具是否经过同一领域校验？无效输入是否会改动现有状态？
3. 容器变化、明暗切换或应用形态变化是否不必要地重建运行实例或清空数据？
4. 历史数据的处理是否可解释、可撤销？是否误删与本次外观修改无关的内容？
5. 测试是否实际观察改动后的公开行为？浏览器视觉判断是否有实测依据？

主要证据入口：[tools.ts](../../../src/lib/tools.ts)、[workspaceStore.ts](../../../src/lib/workspaceStore.ts)、[applications.ts](../../../src/lib/applications.ts)、[runner.ts](../../../src/lib/applet/runner.ts)。
