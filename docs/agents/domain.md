# 领域文档读取规则

本项目采用单领域文档，入口为根目录 [GLOSSARY.md](../../GLOSSARY.md)。记录页面、组件、应用、运行形态、特效图层等产品术语，术语表不放实现路径或需求清单。

重要取舍记录在 [docs/decisions](../decisions/README.md)，这是 Matt 技能默认 `docs/adr/` 的项目映射。只有改变成本高、没有背景容易误解、确有方案取舍的决策才写 ADR。

探索和实现前：

1. 读术语表，避免把 Applet、页面小组件、应用目录记录混为一谈。
2. 读相关 ADR 与 `docs/specs/`；区分现状和尚未实现的目标契约。
3. 读相关 `.trellis/spec/` 与任务上下文；执行证据写入任务，不复制为长期规范。
4. `docs/design-system.md` 是运行时会读取的设计规范，引用它而不再维护另一份副本。

产品术语与现有实现矛盾时，先明确差异，不能悄悄把规划写成事实。新决策被接受后更新长期文档；历史研究保留其日期和检查范围。
