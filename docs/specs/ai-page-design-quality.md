# AI 页面生成质量目标

决策状态：`accepted`（2026-10-27）。实现状态：`in-progress`（设计指引已修正，其余增强仍在规划），现有基础与待补能力按下表区分；具体交付以 Trellis 任务及其验证记录为准。

目标是让 AI 能持续生成符合用户风格、实际容器和系统交互的页面，并依据检查结果修正。评价依据是内容与操作是否成立，不以特效数量或组件库数量衡量。

## 现状与目标的分界

| 领域 | 已有基础 | 需要交付的增强 |
| --- | --- | --- |
| 设计指引 | 统一设计规范、系统提示词与工具说明；本轮已修正矛盾示例 | 后续新增能力继续保持目录、工具示例与规范一致 |
| 响应式 | 页面响应式、Applet 容器宽度和 Grid 收列 | 将窄容器要求纳入素材说明、布局组合及检查结果 |
| 特效 | 参数校验、懒加载、部分组件的减弱动画与暂停 | 统一能力说明、组合预算、主题策略和内容降级 |
| 页面编辑 | 工作空间操作、撤销、模板 | 支持更有语义的布局组合，逐步补齐草稿和检查后应用的流程 |
| 验收 | 源码与配置核对 | 先提供结构与渲染测量反馈，后续再增加截图反馈 |
| 数据展示 | 简单柱状图和表格 | 可配置的通用图表、数据列表与表格能力 |

## 统一的使用规则

1. **信息与操作优先。** 默认页面有清楚的主次，保留用户已有内容；特效不得成为访问文字或操作的前提。默认工具示例沿用主题 token，不主动鼓励大圆角、重阴影、固定主题底色或重复装饰。
2. **按实际容器适配。** 手机、AI 分栏、抽屉、弹窗和页面小组件都可能是窄容器。内容不能依赖浏览器窗口宽度，也不能只在 hover 时可见；触屏与键盘均有可用操作路径。
3. **双主题可读。** 特效和新增组件使用语义色板，或明确声明浅色、深色配置。不能把默认色适配推断成任意自定义色都安全。
4. **减少动画仍有内容。** 减少动态效果时，持续、滚动或指针驱动动画按登记策略降级；文字应落在完整可读状态。动画加载或渲染失败时，标题、数字与正文保留静态内容。
5. **组合预算由系统执行。** 图层与内容块都纳入同一页面的统计；运行时限制依据效果成本与容器能力，不能靠增加内容块绕过预算。具体阈值由任务设计、测量与验证确定，不在文档中虚构性能承诺。
6. **可发现才算可用。** 新能力同时提供稳定接口、参数校验、AI 目录说明、主题与容器行为以及示例。新增依赖或复制源码本身不视为交付 AI 能力。

## 特效目录必须说明什么

每个纳入目录的素材应说明：适用位置、渲染方式、交互依赖、窄容器及触屏替代方案、减少动画策略、主题配色、暂停与资源清理策略、失败时替代内容，以及来源版本和许可。具体字段随实施设计确定，避免提前冻结未经验证的 schema。

宿主应在适用场景内落实质量限制，模型不能通过参数绕过安全上限。重型场景按明确需求选择；素材没有对应适配时，目录应如实说明，并提供可用替代，而不是声称整套库天然支持所有设备。

## 检查与修正

生成后的检查首先提供可验证的事实：检查时的页面与容器、主题和减少动画状态，溢出或裁切问题，以及特效组成与约束违反。每个问题应定位到相关页面或组件，给出可采取的修正方向。

检查报告必须区分：

- 已读取配置或源码；
- 已在某个真实尺寸下测量渲染结果；
- 已查看截图或进行人工视觉检查；
- 未覆盖或无法自动判断的内容。

不得把 DOM 尺寸检查等同于审美、复杂背景对比度或完整无障碍验收。尚无截图能力时，应明确说明；不能伪造视觉通过结论。

## 布局与扩展组件

布局能力优先覆盖主视觉、分区、主次分栏、快捷操作和信息集合，使 AI 能选择极简启动页、效率工作台、编辑式内容页或视觉展示页，再按用户内容调整。每个组合应定义窄容器重排、长标题、空数据和主题行为。

功能扩展优先于继续增加相似装饰：通用图表扩展现有简单柱状图，数据列表扩展现有简单表格；图片浏览、精选视觉组件与动画资产按实际任务纳入。基础交互继续沿用宿主控件，避免并存多套按钮、表单和主题规则。

## 验收覆盖

基准页面至少覆盖 320px、375px、768px 和桌面宽度，并覆盖桌面窗口内的窄分栏或抽屉；这是验证矩阵，不要求实现把这些值全部作为断点。

同一方案核对浅色、深色、减少动画、触屏或无悬停、长内容与空数据状态。文本特效失效时内容保留；装饰关闭不影响操作。只针对外部可观察行为编写必要回归，不用测试逐字锁死自然语言提示词。

沿用现有模板和撤销基础，页面改造不能损坏组件业务数据或应用身份。未来草稿预览流程不得把试验状态提前写进正式设计。
