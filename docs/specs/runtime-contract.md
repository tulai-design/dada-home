# 搭搭运行时契约

状态：当前有效行为。核对日期：2026-10-28。本文描述现有实现；下一阶段的目标见 [AI 页面生成质量](ai-page-design-quality.md)。

## 工作空间编辑

- 页面持有有序组件实例，以及可选的分区、壁纸、特效图层、页面样式和对齐设置。首页固定存在并保持第一位。
- 组件配置由注册目录声明，修改时经过参数校验与规整。应用目录独立于页面挂载，不能根据“页面里没有它”判定应用未安装。
- AI 通过工具访问工作空间。工作空间编辑由操作函数或应用管理函数生成新状态，再提交给工作空间 store；不由模型直接修改 React 状态或本地存储。
- 工作空间提交进入撤销/重做历史。组件业务数据、会话、外部服务操作有各自的存储与行为，不能把工作空间撤销理解为对所有副作用的回滚。
- 页面图层整体替换，最多三层；图层与内容特效共用页面组合预算，经过目录参数与预算校验。

依据：[workspace](../../src/lib/workspace.ts)、[tools](../../src/lib/tools.ts)、[ops](../../src/lib/ops.ts)、[workspaceStore](../../src/lib/workspaceStore.ts)、[applications](../../src/lib/applications.ts)。

## 页面分区

- 可选的 `Page.sections` 通过组件 ID 组合主视觉 `hero`、内容分区 `section`、主次分栏 `split`；组件实体仍只保存在 `Page.components`。旧页面继续使用原有扁平网格，不自动改版。
- `list_page_layouts` 公开目录与约束；`set_page_sections` 校验后整体替换分区。每页最多八个分区、一个主视觉；组件引用必须属于当前页且不能重复。空分区不产生标题或占位，未分组组件保留在末尾。
- 阅读顺序依次为分区顺序、分区内组件顺序、未分组组件顺序；主次分栏先主栏后辅栏。该顺序同步到组件列表和 DOM，作为窄容器与键盘访问顺序。新增或移动到某个索引会进入该位置组件所在的槽位，移到全页末尾则成为未分组组件。
- 内容分区支持一至三列；主次分栏支持等宽或 2:1，按行配对。实际内容容器小于 720px 时叠成单列，适用于手机和桌面 AI 分栏。布局切换保留组件的渲染父节点与 ID，不因分组而重建业务实例。
- 保存、撤销、恢复和模板均保留分区。内置模板更换组件 ID 时同步更换引用；删除、跨页移动、应用卸载或取消挂载会清理引用。`sections: null` 或 `[]` 清除分区，保留当前组件顺序、宽度、配置和数据。

依据：[分区规则](../../src/lib/pageSections.ts)、[布局计划](../../src/lib/pageSectionLayout.ts)、[PageView](../../src/components/PageView.tsx)。具体 AI 操作示例只在[设计规范](../design-system.md)维护。

## 首页组合与布局草稿

- 四类首页组合为极简启动、效率工作台、编辑式内容和视觉展示；按既有内容类型或显式焦点组织分区。仅调整当前首页的分区及阅读顺序，保留所有组件 ID、配置、外观、图层、壁纸与应用身份，不自动安装或编造业务内容。
- 草稿是独立内存状态，创建、调整、预览与取消均不提交正式工作空间或历史，刷新后丢弃。重选方向从创建时的内容顺序生成；手工调整分区基于当前草稿。已有草稿不能被新的创建请求静默替换。
- 修改和应用需要对应草稿 ID 与最新 revision。应用前检查正式首页是否已改变；冲突拒绝覆盖并保留草稿。成功时只向最新工作空间合并首页布局，一次提交可撤销，其他页面、主题和应用设置的修改保留。
- 预览复用真实页面分区布局和当前主题，但内容采用配置的静态表示或类型占位。不会启动第二份业务组件、读取私有业务值、取数或运行应用/特效；正式页面保留挂载和原输入状态。壁纸、动态效果、真实数据高度和应用内部不在预览范围。
- 命令面板「预览首页方案」或 AI 创建草稿均可打开预览；面板支持切换组合、检查、应用、取消。`inspect_homepage_draft` 测当前挂载草稿的外框，返回 target、revision、实际容器、主题及静态覆盖未知项；与正式 `inspect_page` 分开，未挂载、取消或陈旧版本不冒充已测量。

依据：[首页组合](../../src/lib/homepageRecipes.ts)、[草稿生命周期](../../src/lib/homepageDraft.ts)、[预览](../../src/components/HomepageDraftPreview.tsx)、[草稿检查](../../src/lib/homepageDraftInspection.ts)。隔离取舍见[决策 0003](../decisions/0003-homepage-draft-isolation.md)。

## 主题、外观与模板

- 默认主题不可直接覆写；新风格保存为独立主题。主题区分共有参数与浅色、深色配色分支，明暗切换不是重新创建页面。
- `get_appearance` 返回默认、当前和差异；`reset_appearance` 按全局或首页范围恢复默认装饰。默认保留当前明暗模式；仅首页还原不能顺带改变全局明暗。
- 外观还原保留页面内容、组件配置与顺序、布局宽度和对齐、业务数据、主题库与模板库。独立特效块与自编应用是内容，仍保留，并由外观报告指出需要单独检查。
- 模板保存设计快照，可以包含主题与应用目录等设计数据；不包含待办、便签和应用私有数据等完整业务数据。应用模板会替换对应设计，不能当作数据合并操作。

依据：[themes](../../src/lib/themes.ts)、[appearance](../../src/lib/appearance.ts)、[templates](../../src/lib/templates.ts)。具体视觉 token 与写法只在[设计规范](../design-system.md)维护。

## 应用目录、入口与运行形态

- 创建 Applet 或 App 默认安装进组件市场的应用目录，不自动新建页面或固定 Dock。
- 应用可以分组、配置默认打开方式和设置，按需增加 Dock、状态栏入口或页面小组件。一个应用最多挂载一个页面；取消挂载保留安装记录。
- 主窗口支持弹窗、抽屉、全页面；运行形态还包括页面小组件与状态栏紧凑视图。应用必须按当前容器布局，不能把所有形态当作浏览器全屏。
- 桌面弹窗的标题栏、交通灯、拖动、最小化和最大化由宿主提供，应用内容不重复绘制。最小化隐藏主窗口并保留该运行实例。
- 状态栏默认是启动入口；启用紧凑视图前，源码必须实现单行内容。主窗口或可见页面小组件运行时，同一应用的紧凑视图回退为入口，避免并发写状态。
- 切换形态可能重新挂载；只有显式持久化的数据保证保留。所有运行形态卸载后，不提供后台常驻计时器、轮询或通知。
- 卸载移除应用目录及入口，保留本机私有数据并支持工作空间撤销；不能把“卸载”宣传成私有数据擦除。

依据：[ApplicationHost](../../src/components/ApplicationHost.tsx)、[ApplicationWindow](../../src/components/ApplicationWindow.tsx)、[应用管理](../../src/lib/applications.ts)。

## Applet 与 App 的边界

| 行为 | Applet | 沙盒 App |
| --- | --- | --- |
| 界面 | 在目录内声明界面积木，由宿主渲染 | 隔离 iframe 内的 HTML/CSS/JavaScript |
| 主题 | 使用宿主控件与主题，逻辑可读 `ctx.dark` | 注入主题变量与 `tada.dark`，主题变化通过消息与 `tada:themechange` 更新 |
| 容器 | `ctx.viewport.width/compact`；Grid 按自身容器收列 | 在 iframe 内容宽度内使用响应式 CSS |
| 形态 | `ctx.surface` | `tada.surface` |
| 持久业务数据 | 显式声明 `persist` 字段 | `tada.store` |
| 用户设置 | 只读 `ctx.settings` | 只读 `tada.settings` |
| 设置变化 | 更新上下文并重渲；实际变化后调用 `onSettingsChange`，不重跑 `init` | 配置变化后安全重载，私有持久数据保留 |

Applet 的尺寸变化只触发布局更新，不重新初始化业务状态。`view` 负责生成界面，取数与定时任务不放在 `view`；设置依赖的副作用在设置变化时取消旧任务并重建。应用设置支持字符串、数字、布尔值与选项字段，由宿主生成设置表单。

App 不具有宿主同源权限，数据与宿主交互经过桥接。Applet 逻辑运行在隔离环境，界面只能使用已登记积木；两者都不应把沙盒内的临时存储当作持久存储。

依据：[Applet 目录](../../src/lib/applet/catalog.ts)、[Applet runner](../../src/lib/applet/runner.ts)、[App 运行时](../../src/widgets/app.tsx)、[应用设置](../../src/components/ApplicationSettings.tsx)。

## AI 应用存储现状

内置组件数据与聊天记录已使用IndexedDB，但AI应用尚未统一到该链路：Applet的persist经store.ts写入localStorage的`fp.applet.<id>`，HTML App的tada.store直接写入`fp.app.<id>`。两者的`MAX_STORE = 100_000`是宿主人为限制，判断依据为JSON字符串长度，并非精确字节数或IndexedDB配额。

Applet的store.ts在localStorage写入失败时保留最新内存值，同时登记可见失败和重试；尚未保存成功不等于落盘。HTML App仍走独立桥接保存链路。后续将独立处理AI应用IndexedDB存储、逻辑身份、备份及容量策略；用户允许新模型，不要求旧实例迁移或双写。当前数据表能力不改变此存储位置，也不把100KB描述为浏览器容量。

依据：[Applet保存](../../src/widgets/applet.tsx)、[App保存](../../src/widgets/app.tsx)、[旧存储工具](../../src/lib/store.ts)、[组件IndexedDB存储](../../src/lib/componentData.ts)。

## 本地保存与恢复

- 数据库请求与事务均成功才确认落盘；读取失败会抛错，与真实空值区分。数据库升级被旧标签页阻挡时允许关闭旧页后重试；启动读取失败显示恢复入口，不进入空白或可编辑的默认库。
- 组件和聊天待写项串行提交，失败保留最新版本，可通过宿主提示重试；聊天轮次在编辑时绑定原会话。旧数据仅在目标提交并读回核验后清除。损坏的旧组件配置保留原文并告警，不阻断其他合法迁移。
- 完整备份和同步先等待组件、聊天及配置的保存屏障。故障不会被当成空库上传，也不会据此生成删除。导出不中断流式回答，包含屏障前已接受的更改；屏障后的并发改动可能进入此次或下一次快照，localStorage 与 IndexedDB 不具有共同原子快照。
- 新备份以 `app: dada-backup`、`version: 1` 标识；合法旧格式仍可导入。未知版本、缺表、坏行、重复 ID、孤立聊天轮次、非字符串配置和超过 256 MiB 整包预算的文件在替换前拒绝。该预算与存储配额无关。
- 恢复与重置用独立 `recovery` 仓保护原快照，在一个 IDB 事务中写日志并替换业务表，再替换配置，最后删日志并重载。失败尝试回退；回退也失败时保留日志并停止业务编辑，重新加载在业务初始化前重试回退。恢复日志不参加备份或同步。
- 恢复与启动检查通过同源 Web Lock 协调，防止新标签页误把活跃恢复当中断。已打开标签页的业务写没有跨标签协作保证，恢复前必须停止生成并关闭其他搭搭标签页；无 Web Locks 时拒绝恢复，正常无日志启动仍可用。
- 原样导出的损坏配置用于救援，不保证直接满足严格导入校验。启动错误页可导出本地配置及未迁移旧值，明确不包含数据库聊天，不作为完整备份导入。

依据：[数据库](../../src/lib/db.ts)、[保存状态](../../src/lib/persistence.ts)、[聊天](../../src/lib/chat.ts)、[备份](../../src/lib/storage.ts)、[共用恢复提交](../../src/lib/storageCommit.ts)、[提示与启动恢复](../../src/components/PersistenceNotice.tsx)。聊天分页和 AI 应用搬库仍是后续任务。

## 快照同步

- 当前格式为 `dada-sync-v2.json`，正文标识 `app: dada-sync`、`version: 2`，明确 `scope`、密钥策略和逻辑记录。未知版本、范围、目标、值或聊天关联在提交前拒绝；不读取旧同步文件或迁移旧 meta。
- Gist 固定配置范围，包括页面设计、应用源码和设置、宿主偏好与当前性格。聊天、画像、累积记忆、组件与应用业务状态不进入配置快照，也不能借伪造记录入站。WebDAV / HTTP 为完整范围，包含可携业务数据与已结束轮次；生成中轮次延后处理，不把暂缺的结束状态当删除。
- 记录身份包括 config、component、app、conversation、turn；App 与 Applet 同名实例隔离。逻辑计数和设备标识比较版本，同版本不同内容以摘要确定排序；墓碑不按时间自动清理。首次连接时远端同身份优先，本机独有记录保留并上传。元数据按资源、范围和协议隔离，不绑定当前物理存储 key。
- 本机网络授权、连接与运行状态始终排除，入站保留本机值。默认排除已知凭据；同步凭据必须加密。应用源码、业务 JSON 和自由文本可能含用户手写敏感内容，不承诺自动识别。添加、轮换或移除加密、关闭密钥同步会改写最新快照表示；原云端口令仅在本次内存中用于解密，不保证擦除供应商历史。
- 加密信封使用 PBKDF2-SHA256、210000 次迭代、16 字节盐、AES-256-GCM、12 字节 IV 和 128 位标签，信封版本与算法/参数严格校验。口令错误或密文损坏时不改本机或远端。
- 网络期间本机数据或连接变更会停止旧操作；首次上传前持久化采样基线，确保上传期间的新编辑在失败后重试或重载后重试也不被旧云端值覆盖。入站在保存门禁内复查，借用独立恢复日志提交；仅配置提交的恢复点不读取聊天和组件业务仓。拉取成功后在释放门禁前进入只读待重载状态；由用户明确刷新，防止旧缓存写回，也避免自动重载清掉输入。
- WebDAV / HTTP 初次创建使用 `If-None-Match: *`，更新仅以强 ETag 发送 `If-Match`。Gist 及没有强 ETag 的服务标为无并发保护。冲突有界重试；限流和服务失败给出重试时间，冷却期零网络，不长时间阻塞本机保存。
- 自动同步仅定期上传；完整拉取由手动同步触发。每次读取完整快照，有变更时完整写回，尚无增量服务。UTF-8 正文预算 Gist 8 MiB、WebDAV / HTTP 64 MiB，不是供应商或浏览器配额。Gist metadata、raw、出站 JSON 包装均校验；显示 Fetch 可见正文字节，不包含 HTTP 头或压缩后的物理流量。连接测试只读；Gist 无 ID 时未验证令牌，首次同步才创建。

依据：[同步协调](../../src/lib/sync.ts)、[协议](../../src/lib/syncProtocol.ts)、[记录投影](../../src/lib/syncData.ts)、[网络提供方](../../src/lib/syncProviders.ts)、[同步设置](../../src/components/SyncSettings.tsx)。可供其他项目共用的增量服务属于后续独立阶段。

## Applet 趋势图

LineChart以宿主积木提供有界折线展示，沿用目录→沙盒声明→宿主渲染链路；Bars保持原有简单柱状行为。标签按输入顺序等距排列，最多120点、4条同单位系列；超量或数据不合法显示局部错误，要求调用方整理数据，不静默截断。

零、负数是有效值，null为缺失并断线。空/全缺失不会画成零趋势；单点和常数仍可见。图形、轴与图例使用宿主主题变量，图例另用线型区分；刻度随实际内容宽度减少，完整标签和精确值可在键盘/触摸可展开的数据表中读取。

图表只消费数据，不发请求或写业务状态。宽度与主题变化只更新展示；状态栏应由应用返回简短数字。AI技能含共享源码的本地记录示例，用户输入后持久化，默认不在用户工作空间自动安装。

## Applet 数据管理

DataTable独立于原有简单Table，复用Lobe表格和控件。列为纯数据定义，行由稳定ID和标量values组成；最多500行、8列，文本≤500字符、有限数值绝对值≤1e12。非法/超量明确局部错误，不静默截断，不扩大既有100KB业务持久化额度。

应用同时提供state和顶层onChange，回调是局部patch，由应用合并。搜索覆盖全部声明列，包括窄屏隐藏列；先搜索，再稳定单列排序，再分页，null排在末尾。页码从0开始，筛选/排序/页容量变化回到首页；记录删除后有效页码夹到最后一页，选择移除缺失ID，渲染不自动回传修正事件。

选择按ID跨搜索和分页保留，当前页全选只影响当前页，完整已选数可见且可清空。详情按稳定行ID关联，在窄容器保留关键列后仍可读取全部字段；操作支持键盘和触摸。空数据、无匹配和错误分别呈现。

共享记录示例将records与ID计数持久化，搜索/排序/页码/选择保持临时状态；设置变更只更新相关视图，不重新初始化数据。表格自身没有网络或业务存储副作用，尺寸与主题更新不重启runner。

## AI 可确认的结果

当前工具可以读取工作空间、源码、设置和入口，并确认操作是否成功。`inspect_page` 额外测量当前已挂载页面的真实容器、主题、减少动画和组件外框，并以稳定问题标识支持修复后复查。检查不导航、不修改工作空间和历史，也不读取正文、聊天或私密表单值。其他未挂载页面、隐藏或布局不同步会明确不可测；iframe/Canvas 内部、文字对比度和审美保持未知。应用内 AI 没有浏览器截图反馈，配置合法或几何问题清空不等于手机、明暗主题或键盘体验已全部验收。

特效渲染已有统一能力目录、页面图层与内容块共用预算、语义与双模式配色、窄容器和减少动画等静态降级，以及已识别加载/图形失败的说明与重试；具体边界见 [设计规范](../design-system.md) 和 [特效规范](../../.trellis/spec/ai/effects.md)。检查器只采页面根节点内的宿主特效标记，不能推断帧率、真实绘制结果或背景 portal 的完整状态。
