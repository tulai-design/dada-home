# 搭搭运行时契约

状态：当前有效行为。核对日期：2026-10-27。本文描述现有实现；下一阶段的目标见 [AI 页面生成质量](ai-page-design-quality.md)。

## 工作空间编辑

- 页面持有有序组件实例，以及可选的壁纸、特效图层、页面样式和对齐设置。首页固定存在并保持第一位。
- 组件配置由注册目录声明，修改时经过参数校验与规整。应用目录独立于页面挂载，不能根据“页面里没有它”判定应用未安装。
- AI 通过工具访问工作空间。工作空间编辑由操作函数或应用管理函数生成新状态，再提交给工作空间 store；不由模型直接修改 React 状态或本地存储。
- 工作空间提交进入撤销/重做历史。组件业务数据、会话、外部服务操作有各自的存储与行为，不能把工作空间撤销理解为对所有副作用的回滚。
- 页面图层当前整体替换，最多三层。目录校验效果类型和参数；这只是结构限制，尚不构成统一的页面性能预算。

依据：[workspace](../../src/lib/workspace.ts)、[tools](../../src/lib/tools.ts)、[ops](../../src/lib/ops.ts)、[workspaceStore](../../src/lib/workspaceStore.ts)、[applications](../../src/lib/applications.ts)。

## 主题、外观与模板

- 默认主题不可直接覆写；新风格保存为独立主题。主题区分共有参数与浅色、深色配色分支，明暗切换不是重新创建页面。
- `get_appearance` 返回默认、当前和差异；`reset_appearance` 按全局或首页范围恢复默认装饰。默认保留当前明暗模式；仅首页还原不能顺带改变全局明暗。
- 外观还原保留页面内容、组件配置与顺序、布局宽度和对齐、业务数据、主题库与模板库。独立特效块与自编应用是内容，仍保留，并由外观报告指出需要单独检查。
- 模板保存设计快照，可以包含主题与应用目录等设计数据；不包含待办、便签和应用私有数据等完整业务数据。应用模板会替换对应设计，不能当作数据合并操作。

依据：[themes](../../src/lib/themes.ts)、[appearance](../../src/lib/appearance.ts)、[templates](../../src/lib/templates.ts)。具体视觉 token 与写法只在[设计规范](../design-system.md)维护。

## 应用目录、入口与运行形态

- 创建 Applet 或 App 默认安装进组件市场的应用目录，不自动新建页面或固定 Dock。
- 应用可以分组、配置默认打开方式和设置，按需增加 Dock、状态栏入口或页面小组件。一个应用最多挂载一个页面；取消挂载保留安装记录。
- 主窗口支持弹窗、抽屉、全页面；运行形态还包括页面小组件与状态栏紧凑视图。应用必须按当前容器布局，不能把所有形态当作浏览器全屏。
- 桌面弹窗的标题栏、交通灯、拖动、最小化和最大化由宿主提供，应用内容不重复绘制。最小化隐藏主窗口并保留该运行实例。
- 状态栏默认是启动入口；启用紧凑视图前，源码必须实现单行内容。主窗口或可见页面小组件运行时，同一应用的紧凑视图回退为入口，避免并发写状态。
- 切换形态可能重新挂载；只有显式持久化的数据保证保留。所有运行形态卸载后，不提供后台常驻计时器、轮询或通知。
- 卸载移除应用目录及入口，保留本机私有数据并支持工作空间撤销；不能把“卸载”宣传成私有数据擦除。

依据：[ApplicationHost](../../src/components/ApplicationHost.tsx)、[ApplicationWindow](../../src/components/ApplicationWindow.tsx)、[应用管理](../../src/lib/applications.ts)。

## Applet 与 App 的边界

| 行为 | Applet | 沙盒 App |
| --- | --- | --- |
| 界面 | 在目录内声明界面积木，由宿主渲染 | 隔离 iframe 内的 HTML/CSS/JavaScript |
| 主题 | 使用宿主控件与主题，逻辑可读 `ctx.dark` | 注入主题变量与 `tada.dark`，主题变化通过消息与 `tada:themechange` 更新 |
| 容器 | `ctx.viewport.width/compact`；Grid 按自身容器收列 | 在 iframe 内容宽度内使用响应式 CSS |
| 形态 | `ctx.surface` | `tada.surface` |
| 持久业务数据 | 显式声明 `persist` 字段 | `tada.store` |
| 用户设置 | 只读 `ctx.settings` | 只读 `tada.settings` |
| 设置变化 | 更新上下文并重渲；实际变化后调用 `onSettingsChange`，不重跑 `init` | 配置变化后安全重载，私有持久数据保留 |

Applet 的尺寸变化只触发布局更新，不重新初始化业务状态。`view` 负责生成界面，取数与定时任务不放在 `view`；设置依赖的副作用在设置变化时取消旧任务并重建。应用设置支持字符串、数字、布尔值与选项字段，由宿主生成设置表单。

App 不具有宿主同源权限，数据与宿主交互经过桥接。Applet 逻辑运行在隔离环境，界面只能使用已登记积木；两者都不应把沙盒内的临时存储当作持久存储。

依据：[Applet 目录](../../src/lib/applet/catalog.ts)、[Applet runner](../../src/lib/applet/runner.ts)、[App 运行时](../../src/widgets/app.tsx)、[应用设置](../../src/components/ApplicationSettings.tsx)。

## AI 可确认的结果

当前工具可以读取工作空间、源码、设置和入口，并确认操作是否成功。应用内 AI 没有浏览器截图或视觉测量反馈；打开页面不是观察页面，配置合法不等于手机、明暗主题或键盘体验已通过验收。

特效渲染已有懒加载与错误隔离，多种效果有减少动画和暂停逻辑；这些是具体组件的实现事实，不能推断所有效果、所有组合都自动具备相同保证。统一预算、色板策略、内容降级与页面检查属于下一阶段目标。
