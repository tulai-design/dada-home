# 自建加密增量同步

核对日期：2026-10-29。入口在设置的「同步」页，作为一种同步方式：粘贴管理页生成的一把同步密钥。管理页用管理员令牌登录，每个已授权的应用是一个服务、各有一把密钥。应用标识、设备和邀请不出现在搭搭设置里。不开启同步时仍完整支持纯本地使用。

## 数据与协议

App / Applet 的 canonical 身份仍为 `app:<id>` / `applet:<id>`。服务端 `applicationData` 集合使用 JSON 转义后身份的 SHA-256；加密元数据携带原始身份并在入站核验。已有 1000 个 JS 字符的身份上限不缩减，孤立 surrogate 不被 UTF-8 替换后误合并。

应用状态先按现有 JSON、8 MiB UTF-8、100 层边界校验，保留完整业务字段。完整状态进入分块加密对象，记录只承载加密元数据和对象引用。认证、对象哈希、引用、身份或结构任一失败，整页不应用、不推进游标。当前应用协议一个操作只包含一条记录；多记录批次在下载对象前拒绝，不能将通用服务能力误当作本产品已支持。

删除通过加密的逻辑墓碑表示；新设备能恢复它对应的原始身份。保存 `{}` 仍是一条有效状态。卸载应用继续保留业务数据；单应用业务删除是单独的程序操作，不改变卸载含义。

## 本机持久化与重试

IndexedDB 的 `apps` 保存业务，`applicationSync` 保存本机绑定、generation、待发意图、准备好的不可变请求/密文、上传检查点、冲突双方和游标。这些协调数据不进入普通五仓备份。

- 应用保存与待发意图在同一事务提交；失败一并回滚，现有保存队列保留最新值供重试。
- 首次绑定读取已有应用状态作为种子；之后只处理持久待发意图。
- 操作 ID、基线版本和随机密文在首次发送前固定落库。丢响应时先查询原操作，不能重新加密后复用同一个 ID。
- 后继编辑有自己的 generation；旧操作确认只清自己对应的意图，不清掉新编辑。
- 入站先在事务外下载/解密，再在事务里重新读取当前值、队列与版本，保存业务、冲突、版本和游标。
- 同源旧缓存用持久 generation 比较后写入；版本不匹配明确拒绝。它不是多个活跃界面的实时协作或自动合并。

## 完整业务范围与冲突

离线两端修改同一应用，或者一端删除另一端修改，都保留本地和远端候选。选择本地或远端时，必须提交检查时看到的 `localGeneration` **与** `remoteRevision`；任一变化则拒绝旧选择。不会自动按时间决定覆盖。

自建增量同步始终在客户端加密，默认开启全部五类集合，不复用 Gist/WebDAV 快照的脱敏投影：

- `config`：工作空间（主题库、当前深浅模式、页面背景/CSS/特效、应用定义与设置、Dock/状态栏、模板）、宿主设置、AI 的 API Key/服务地址/extraBody、搜索的 keys/urls、监控/代理、性格/记忆/画像，以及稳定偏好。
- `component`：全部组件业务值，包含 ICS 订阅地址等凭据；`applicationData`：App/Applet 完整 JSON，包括名为 keys/token 的普通业务字段。
- `conversation` / `turn`：全部会话与轮次，工具正文和轮次作为同一个加密实体。

凭据清空或删除随完整值传播，不能从目标设备旧值里偷偷补回。配置仍使用显式白名单和运行时校验，不接受任意 localStorage key。`workspace.network` 与 `alwaysAllow` 是本机操作授权，不跨设备授予；当前页面/会话、运行中计时、缓存、恢复日志和同步队列也保留本机。

同步设备令牌、连接绑定和空间加密密钥与业务 API Key 不同。它们不作为业务记录复制。同一服务只有一把加密密钥，放在同步密钥里；服务器已有数据时，管理页拒绝再新建一把。换设备时粘贴原来的同步密钥。本机若还留着旧设置中能解开这些数据的空间密钥，手动同步会换回它。当前绑定的密钥摘要固定，密钥轮换仍不在本轮交付范围。

离线冲突保留完整双方；界面摘要遮盖已知凭据字段。选择本地或远端时校验观察版本，不静默覆盖。

## 程序生命周期

核心入口为 `createIncrementalSyncController`，设置页通过 `runIncremental` 调度：

- `bind()`：本机绑定目标、空间、设备、密钥摘要并播种已有业务记录；不自动联网。
- `run({signal, maxPush, maxPull})`：默认最多推送 20 个操作、接收 1 页；单页只解密 1 个提交。设置页先分批上传，再以 `maxPush: 0, maxPull: 10000` 连续拉取。手动操作的上传/拉取各有 10000 条预算；耗尽且仍有数据时明确显示未完成，保存进度供下一次继续。返回 `pushed/pulled/conflicts/hasMore/needsReload`；`hasMore` 包含未冲突的本机队列。
- `inspect()`：读取当前绑定与候选；`resolve(ref, {localGeneration, remoteRevision}, choice)` 明确解决冲突。
- `close()`：取消运行，持久队列保留；可创建新控制器继续。
- `detach()`：显式解绑，保留旧 epoch 的待发请求与冲突供程序检查；之后继续纯本地。再次绑定使用新 epoch 和本地种子，远端已有记录按冲突处理。

运行、绑定、解绑和恢复共用 Web Lock；网络/解密期间仍允许本地编辑。入站应用前短暂禁止新写入并排空已接受保存，这段时间不盖全屏。有业务变化则设置已有 `sync-reload` 门禁，避免旧内存写回；用户没在输入时页面自行重新加载，正在输入则等离开输入框再加载，不再弹出确认。不能仅写入数据库后允许旧 iframe/内存继续保存。手动同步在同一轮完成连续分页，不能在首条入站后重新经过写入断言而提前停止。后续分页不再次 flush 旧业务缓存；失败或预算耗尽也保留已经发生的重载保护。

绑定期间，备份导入或旧整包同步涉及已接入业务表会明确拒绝，须先显式解绑；恢复、回退与旧快照应用同事务提升受影响应用的 generation。恢复日志只回退本次实际触及的数据表，不能为配置失败顺带恢复未改动的应用表。
