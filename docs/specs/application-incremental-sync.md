## 数据与协议

App / Applet 的 canonical 身份仍为 `app:<id>` / `applet:<id>`。服务端 `applicationData` 集合使用 JSON 转义后身份的 SHA-256；加密元数据携带原始身份并在入站核验。已有 1000 个 JS 字符的身份上限不缩减，孤立 surrogate 不被 UTF-8 替换后误合并。

应用状态先按现有 JSON、8 MiB UTF-8、100 层边界校验，再投影已知凭据字段。完整状态进入分块加密对象，记录只承载加密元数据和对象引用。认证、对象哈希、引用、身份或结构任一失败，整页不应用、不推进游标。当前应用协议一个操作只包含一条记录；多记录批次在下载对象前拒绝，不能将通用服务能力误当作本产品已支持。

删除通过加密的逻辑墓碑表示；新设备能恢复它对应的原始身份。保存 `{}` 仍是一条有效状态。卸载应用继续保留业务数据；单应用业务删除是单独的程序操作，不改变卸载含义。

## 本机持久化与重试

IndexedDB 的 `apps` 保存业务，`applicationSync` 保存本机绑定、generation、待发意图、准备好的不可变请求/密文、上传检查点、冲突双方和游标。这些协调数据不进入普通五仓备份。

- 应用保存与待发意图在同一事务提交；失败一并回滚，现有保存队列保留最新值供重试。
- 首次绑定读取已有应用状态作为种子；之后只处理持久待发意图。
- 操作 ID、基线版本和随机密文在首次发送前固定落库。丢响应时先查询原操作，不能重新加密后复用同一个 ID。
- 后继编辑有自己的 generation；旧操作确认只清自己对应的意图，不清掉新编辑。
- 入站先在事务外下载/解密，再在事务里重新读取当前值、队列与版本，保存业务、冲突、版本和游标。
- 同源旧缓存用持久 generation 比较后写入；版本不匹配明确拒绝。它不是多个活跃界面的实时协作或自动合并。

## 冲突与本机凭据

离线两端修改同一应用，或者一端删除另一端修改，都保留本地和远端候选。选择本地或远端时，必须提交检查时看到的 `localGeneration` **与** `remoteRevision`；任一变化则拒绝旧选择。不会自动按时间决定覆盖。

出入站递归过滤精确字段名 `apiKey`、`token`、`password`、`secret`、`keys`。远端内容先过滤，再恢复本机已有凭据。数组仅按两侧都唯一的非空字符串 `id` 匹配，不能按数组位置搬运秘密。此规则无法识别自由文本里的所有秘密。最终合并再次检查 8 MiB 约束，超限拒绝整个入站页。

令牌、口令和明文 keyring 不持久化到同步仓或普通备份；程序调用方负责每次提供授权凭据与密钥。当前绑定的密钥摘要固定，密钥轮换与设备配对界面还未接入。

## 程序生命周期

入口为 `createApplicationSyncController`：

- `bind()`：本机绑定目标、空间、设备、密钥摘要并播种应用状态；不自动联网。
- `run({signal, maxPush})`：默认最多推送 20 个操作，再接收一个有界页。返回 `pushed/pulled/conflicts/hasMore/needsReload`；`hasMore` 包含未冲突的本机队列。
- `inspect()`：读取当前绑定与候选；`resolve(key, {localGeneration, remoteRevision}, choice)` 明确解决冲突。
- `close()`：取消运行，持久队列保留；可创建新控制器继续。
- `detach()`：显式解绑，保留旧 epoch 的待发请求与冲突供程序检查；之后继续纯本地。再次绑定使用新 epoch 和本地种子，远端已有记录按冲突处理。

运行、绑定、解绑和恢复共用 Web Lock；网络/解密期间仍允许本地编辑。入站应用前短暂禁止新写入并排空已接受保存；有业务变化则设置已有 `sync-reload` 门禁，要求整页重载。不能仅写入数据库后允许旧 iframe/内存继续保存。每次仅接收一个有界页，后续页面在重载后继续。

绑定期间，备份导入或旧整包同步涉及 `apps` 会明确拒绝，须先显式解绑；恢复、回退与旧快照应用同事务提升受影响应用的 generation。恢复日志只回退本次实际触及的数据表，不能为配置失败顺带恢复未改动的应用表。
