# 0003：首页草稿使用布局预览与局部提交

状态：accepted。日期：2026-10-27。

## 背景

首页改版需要先试排、检查，再决定应用或取消。既有模板会替换整套设计，内置模板还会生成新的组件ID；现有PageView会直接启动业务组件。便签、小程序、音乐、计时和取数组件可绕过宿主回调，直接访问共享存储、网络或初始化逻辑。给预览传空回调或禁止点击不能隔离这些副作用。

## 决定

本阶段的首页草稿只保存现有组件的分区及阅读顺序，存于内存。预览复用真实页面布局，内容使用专用静态投影或清楚标示的占位；不启动第二份业务实例、不读取私有业务值，也不预览动态背景或应用内部交互。预览检查的报告显式区分草稿、版本和有限覆盖。

应用时检测正式首页是否发生冲突，然后只向最新工作空间写入首页布局，一次提交复用撤销。其他页、全局主题及应用设置保留；取消和刷新丢弃草稿，不写正式设计或历史。正式首页与草稿可能保留相同组件ID，因此样式和检查定位必须限定各自的页面根。

## 取舍

直接复用完整模板或运行完整副本虽能减少新代码，却会扩大修改范围或共享业务副作用。另建能执行所有应用的完整沙盒，需要独立存储、网络、跨frame协议、主题与运行时隔离，超出本阶段布局组合需求。

静态布局预览能确定层级、排列、实际容器和可见外框；不能保证数据加载后的高度、背景可读性或应用内部功能。界面与AI必须说明限制，不能将占位高度的几何通过推广到正式应用。未来若要预览源码、主题、真实数据或整个工作空间，应另立隔离与冲突契约，不隐式扩展本草稿接口。
