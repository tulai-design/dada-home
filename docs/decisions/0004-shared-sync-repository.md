# 共用同步服务使用独立组织仓库

用户已确认搭搭和 aifenjing 共用可选自建同步服务，并授权用 gh 建立仓库。采用 `tulai-design/sync` 独立组织仓库，产品名 Tulai Sync；服务、协议和轻量客户端 SDK 同仓，两个产品各自维护业务适配器。可见性先设为私有，实现进度以当前增量同步任务记录为准；首个HTTP记录服务已实现，完整产品接入尚未完成。

搭搭当前 `server/` 负责静态部署与只读取数代理，aifenjing 的 ProductStore 负责浏览器/桌面本地业务事务。共用服务的鉴权、版本、对象、游标和部署应有独立的发布周期，不依赖其中一个产品的内部模型。服务不读取客户端数据库文件，也不理解聊天、项目、分镜或素材的业务含义。

## 取舍

| 选择 | 优点 | 代价与结论 |
| --- | --- | --- |
| 放搭搭仓库 | 起步少一个仓库，联调直接 | 服务发布和测试绑定搭搭；aifenjing 依赖另一个产品内部目录，后续拆分还要迁移部署与依赖。不建议。 |
| 放 ai-platform | 复用已有共用仓库 | 存储同步不依赖模型调用，把两种协议和发布节奏绑在一起缺少当前收益。不建议。 |
| 独立组织仓库 | 两个客户端平等接入，独立协议、镜像与发布；支持以后其他本地优先产品 | 需管理跨仓版本及联调。已采用，暂不把服务/协议/SDK再拆成多个仓库。 |

## 归属与后果

- 独立仓库拥有服务协议、通用校验、设备鉴权、应用/空间隔离、版本与幂等提交、分页拉取、不可变对象及持久化部署。SDK提供传输、分页和可重试操作；持久队列与本地应用事务由产品适配器负责。
- 搭搭拥有配置/应用/聊天的同步投影、IndexedDB outbox、入站应用、密钥过滤及冲突界面；aifenjing拥有自己的完整业务投影、ProductStore事务、媒体落盘和运行权限转换。共享SDK不能导入 React、Dexie、Tauri或产品业务类型。
- 服务协议版本、SDK版本和产品数据schema分别管理。产品依赖已验证的固定SDK版本；发布前做两种产品合成投影契约测试，不从另一个产品源码目录直接import，也不以运行时下载GitHub源码联调。
- 独立仓库与同机部署兼容。服务有自己的镜像、进程和持久卷，可在同一份部署编排中与搭搭并列启动；纯本地模式仍不依赖服务。
- 服务仓库承担服务实现任务与协议事实来源；本仓当前Trellis任务继续承担搭搭接入和跨仓验收。aifenjing产品接入在其仓库建立任务，不复制服务PRD或把合成投影测试等同于产品完整接入。

当前源码依据与工作拆分见[仓库归属与接入计划](../../.trellis/tasks/10-28-incremental-sync/repository-layout.md)。HTTP记录协议与Node内置SQLite运行时已在服务仓库定稿并实现，协议正文由服务仓库维护；对象、加密、SDK包与部署仍待后续设计。
