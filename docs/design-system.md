# 搭搭设计规范

这份规范同时约束三类「作者」：写代码的人、写代码的 AI（Cursor 等）、以及搭搭自己在运行时做组件的时候。
应用内的 AI 通过技能 `design-system` 读到的就是这份文件，所以这里的每一条都要能被直接执行，而不是口号。

一句话：**这是一份编辑部风格的纸面界面。** 米白纸张、墨色文字、红色只在最重要的地方出现。信息有主次，留白是设计的一部分，不是剩下的地方。

---

## 1. 控件：一律用 Lobe UI

我们已经装了 `@lobehub/ui`，它的控件自带统一的圆角、焦点、深浅色、动效和无障碍。自己拿原生元素拼，出来的就是「浏览器默认样式」，和整个站点脱节。

| 要做的事 | 用这个 | 不要用 |
| --- | --- | --- |
| 点击动作 | `Button`（文字操作）、`ActionIcon`（只有图标） | `<button>`、`<div onClick>` |
| 几个互斥的档位 | `Segmented` | 自己写的 tab 按钮 |
| 连续的值（音量、进度） | `Slider` | `<input type="range">` |
| 开关 | `Switch` | `<input type="checkbox">` |
| 下拉选择 | `Select` | `<select>` |
| 文本输入 | `Input`、`TextArea` | `<input>` `<textarea>` |
| 日期、时间 | `DatePicker`、`DatePicker.TimePicker` | `<input type="date">` `<input type="time">` |
| 小标签、状态 | `Tag` | 自己画的圆角 span |
| 悬停说明 | `Tooltip` | `title` 属性（只能当兜底） |
| 带表单的小浮层 | `Popover` | 自己写 absolute 定位的面板 |
| 进度 | `Progress` | 自己拼的 div 条 |
| 一个数字加它的说明 | `Statistic` | 自己拼 |
| 没有内容 | `Empty` | 一行灰字 |
| 加载中 | `Skeleton`、`Spin` | 文字「加载中…」 |
| 成组的内容块 | `Block`（可点的用 `clickable`） | 自己写边框和背景 |
| 弹窗 | `Modal` | 自己写遮罩 |
| 图标 | `@phosphor-icons/react`（默认 regular 粗细，需要更轻用 `weight="light"`）配 `Icon` / `ActionIcon`；Phosphor 是填充型图标，全局 CSS 已保证它在 Lobe 的 `Icon` 里正常着色 | emoji 当图标 |

只有在 Lobe 里**确实没有**对应物的结构上，才允许自己画：日历的日期格、环形或柱状的图形（SVG）、封面渐变。即便如此：
- 可点的格子必须能用键盘到达（`role`、`tabIndex`、Enter/Space），并有悬停、选中、聚焦三种状态；
- 颜色、间距、字号仍然只能用下面的 token。

## 2. Token：不写死任何值

**颜色**只用变量，深浅色自动适配：`--bg` `--bg2` `--bg3` `--text` `--text2` `--text3` `--text4` `--border` `--main`（红，强调）以及语义色 `--c-green` `--c-blue` `--c-amber` `--c-violet` `--c-red`。代码里出现 `#xxxxxx` 或 `rgb()` 就是错的（SVG 渐变封面这类生成的颜色例外，且要在深浅色下都看得清）。

**创建主题时**，配色值应写进主题数据：`overrides` 保存共用主色、圆角、外框等；`light` 和 `dark` 分别保存浅色与深色下的 `bg/bg2/bg3`、`text/text2/text3/text4`、`border/rule`，主色需要不同亮度时也分别写入。主题作者可以在这两套数据中定义颜色，组件仍只引用变量。新建完整风格必须照顾两种模式，不能把固定背景和文字颜色塞进一组共享变量，导致切换明暗后颜色不变。

`save_theme` 替换传入的整套分支，未传分支保留；`set_theme` 合并对应分支的补丁，`light: null` 或 `dark: null` 清掉对应分支。`set_theme` 的 `overrides: null` 清空全部共享变量、双模式覆盖和字体。`mode` 仅表示应用主题时的初始偏好，用户之后仍能切换。仅调整字体、圆角或外框可以不传两套配色；缺失的模式配色继承共享变量与系统基础色，不宣称它已有完整的定制设计。改完用 `list_themes` 核对两套数据，再分别检查浅色与深色的文字对比、层级与控件状态。没有实际看过时，明确只完成了数据检查。

**还原默认外观**之前用 `get_appearance` 查看默认资料、当前状态与差异。用户说「还原默认主题」「恢复默认外观」，用 `reset_appearance({scope: "all"})` 恢复纸张主题、默认字体与外框、玻璃 Dock，清理各页壁纸、特效图层、页面 CSS 和组件外观覆盖，并恢复首页默认背景。默认保留用户当前的明暗；明确指定浅色或深色时才传 `mode`。只还原首页背景或装饰用 `scope: "home"`，不改全局主题、Dock 和其他页面。页面内容、组件顺序、宽度、配置、对齐和业务数据都保留，主题库和模板库也保留；不要通过恢复布局、套用模板或删除组件来模拟还原外观。操作后再次读取 `get_appearance` 核对。

用户只想「切到纸张配色」时使用 `apply_theme({ref: "default"})`，它只切换配色与字体，保留已有壁纸、特效等装饰。默认配色、背景和样式的具体数值以 `get_appearance` 返回的资料为准。

独立特效组件、自编 App 和小程序的配置及源码属于页面内容，还原外观时保留。`get_appearance` 会在 `embeddedVisuals` 列出它们；还原后若仍有视觉差异，先检查这些组件的配置或源码，再按用户要求调整，不要声称所有自定义视觉都已消失。

**强调色的用量**：一个组件里红色只给一个东西——当前焦点（正在进行的计时、今天、正在播放的曲目）。其余用墨色和灰。红色用多了就等于没有重点。

**间距**只用 4 的倍数：4、8、12、16、24、32、48。组件内部分组之间 16 或 24，组内元素之间 8 或 12。

**字号**只用这几档：11（极小标注）、12（辅助）、13（列表正文）、14（正文）、18（小标题）、24（大标题）、40、64（焦点数字）。
**字体**：数字、标题、日期用衬线（`var(--font-serif)`），正文和控件用无衬线（Lobe 默认）。表示时间或数量的数字加 `font-variant-numeric: tabular-nums`，避免跳动。

**圆角**：本站是「编辑部」风格——方角、发丝线、不用渐变和毛玻璃。圆角一律读主题变量 `--radius` / `--radius-lg`（现在都是 0），不自定义像素。封面、色块用平涂或极轻的同色相两段色，不用炫彩渐变。

**边线**：1px `var(--border)`；强调的分隔用 `var(--rule)`（墨色）。不用阴影堆层次；阴影只给浮起的东西（弹层、dock）。

**主操作按钮**：给 Lobe `Button type="primary"` 加 `className="ink-button"`，得到墨色实心方块，和主题一致；不要用 Lobe 默认的粉红主色。一个组件里只放一个主操作。红色 `--main` 留给进度、选中这类「焦点」，不给按钮。

## 3. 版式：先定焦点，再排其余

每个组件先回答一个问题：**用户一眼该看到什么？** 那个东西就是焦点，给它最大的字号（40 或 64，衬线）；其余信息按「主信息（14）→ 辅助（12，`--text3`）」两级排，不要出现三个同样重要的东西。

三种组件形态，别混用：

1. **卡片型**：放进栅格，和别的组件并排（待办、倒数日、日程）。宽度由页面决定，不写死像素，半宽也不能溢出。
2. **舞台型**：独占一个页面的主角（番茄钟、音乐）。**必须在页面里水平、垂直都居中**，内容宽度有上限（窄的 ≤ 420px，宽的 ≤ 880px），四周留白。在 `registerComponent` 里声明 `stage: {width: 420}`，页面渲染器负责居中；组件自己不要再写居中的 hack。
3. **状态条型**：顶栏里的一小段，单行、很窄，自己更新。

对齐：同一容器里所有内容共用一条左边线；数字右对齐用等宽数字；图标和文字的基线对齐。

一个页面只有一个组件时，它必须是舞台型；多个组件时，先放最重要的，再放辅助的，不要让每个组件都一样大。

## 4. 状态：每个交互元素都要想完

悬停、按下、聚焦（键盘可见的焦点环）、选中、禁用，以及整个组件的**空、加载、出错**三种状态。

- 空状态用 `Empty`：一句话说清「这里是什么」加一句「怎么开始」，不要只有一个空框。
- 出错要说人话和下一步（「这个地址播不了：可能已失效」，而不是「Error」）。
- 加载用骨架或保留上一次的数据，不要让布局跳动。

## 5. 动效

只做有意义的：状态变化的过渡、焦点数字的更新。时长 100–200ms，缓动用 ease；只动 `transform` 和 `opacity`。所有持续动画（均衡器、呼吸）必须尊重 `prefers-reduced-motion`。

## 6. 无障碍

- 只有图标的控件必须有 `title` 或 `aria-label`，并配 `Tooltip`。
- 文字与背景对比度至少 4.5:1；`--text3` 只用于辅助信息，不用于需要读的内容。
- 所有操作都能只用键盘完成。
- 不用颜色作为唯一的信息载体（休/班用字，不只靠红灰）。

## 7. 文案

中文，短，动词开头（「添加」「开始」「换一句」）。不用感叹号，不用「请」。数字和单位之间不留空格以外的东西（「25 分钟」）。

市场与管理列表只保留名称、必要简介和操作。不放口号、重复的入口说明、打开方式或安装提示；分组集中在筛选栏显示。列表不使用大圆角卡片、色块容器或逐行上边框，靠对齐和间距区分项目。

## 8. AI 造的东西：选对档位

有交互的小工具，**首选小程序（`create_applet`）**：逻辑是 AI 写的 JavaScript，界面只能用积木目录里的 Lobe 控件拼，由主页真实渲染。风格、深浅色、无障碍、点击输入都由系统保证，AI 不用也不能写 CSS。写法见技能 `applet`（积木目录由 `src/lib/applet/catalog.ts` 生成，和实现同源）。

只有这几类才用沙盒应用（`create_app`，iframe）：游戏、Canvas / WebGL / Three.js、需要完全自定义视觉的东西。它必须**模仿**同一套规范：
- 颜色、字体只用主页注入的变量（`--bg` `--text` `--text2` `--text3` `--border` `--main`、`--font-serif`、`--font-sans`）；
- 按钮、输入框、开关自己写时，要有 1px 边线、聚焦环、悬停态，尺寸和 Lobe 的 `middle` 一致（高 32px，字号 14）；
- 沙盒里没有 `localStorage`，存数据用 `tada.store`；复制用 `tada.copy`；
- 同样遵守第 2、3、4、5、6 节。

声明式组件（`create_widget`）直接使用已有的列表、卡片、数字、插图样式，不另写 CSS。

### 应用目录、形态与设置

`create_applet` / `create_app` 默认安装进组件市场的应用目录，不自动创建页面或固定 Dock。创建时 `pageId` 可选，只有用户需要页面小组件时才提供。一个应用保留同一 ID、源码与私有数据，最多挂载一个页面；`mount_application` 的 `pageId: null` 仅取消挂载。编辑前用 `list_applications` 读取目录记录与源码，分组用 `group`，常用入口用 `dock` / `status` 按需开启，管理配置用 `configure_application`。

默认打开方式由 `openMode` 指定：`modal` 弹窗、`drawer` 抽屉、`page` 全页面；在各容器宽度下都应能正常使用。运行时 App 读 `tada.surface`，Applet 读 `ctx.surface`，值为 `widget`、`modal`、`drawer`、`page` 或 `status`。状态栏默认 `statusMode: "launcher"` 只显示启动按钮；需要真实状态视图时，先在源码处理 `surface === "status"`，只显示单行数字、图标或核心状态，再启用 `status: true, statusMode: "compact"`。主窗口或可见页面小组件运行时，宿主暂停同一应用的紧凑视图并回退启动按钮，防止并发写入持久状态。

可配置项使用 `settingsSchema` 声明，`settings` 保存当前值；系统在「设置 → 应用」生成表单，例如：

```json
{"settingsSchema":{"minutes":{"kind":"number","label":"专注分钟","default":25,"min":1,"max":120}},"settings":{"minutes":30}}
```

字段支持 `string`、`number`、`boolean`、`select`；选项字段提供 `options: [{value, label}]`。App 通过只读 `tada.settings` 读取，修改设置后宿主安全重载应用；Applet 通过只读 `ctx.settings` 读取，设置变化更新上下文并重渲，保留 `persist` 状态。设置与业务状态分开，后者仍用 `tada.store` 或 Applet 的 `persist`。打开设置用 `open_settings` 的 `section: "application:<id>"`。卸载使用 `uninstall_application`，移除目录与入口但保留本机私有数据，支持撤销。

## 9. 交付前自检

1. 页面里有没有原生的 button / input / select / range？有就换成 Lobe。
2. 有没有写死的颜色、像素字号、奇怪的间距？
3. 焦点是什么？是不是最大、最显眼的那个？红色是不是只出现了一处？
4. 舞台型组件有没有水平垂直居中？半宽和整宽都不溢出吗？
5. 空、加载、出错、禁用、聚焦都看过吗？
6. 浅色和深色都看过吗？
7. 只用键盘能不能完成所有操作？
8. 在浏览器里亲眼看过，而不是只通过了类型检查。
