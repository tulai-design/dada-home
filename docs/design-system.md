# 搭搭设计规范

这份规范同时约束三类「作者」：写代码的人、写代码的 AI（Cursor 等）、以及搭搭自己在运行时做组件的时候。
应用内的 AI 通过技能 `design-system` 读到的就是这份文件，所以这里的每一条都要能被直接执行，而不是口号。

默认主题是**编辑部风格的纸面界面**：米白纸张、墨色文字、克制的红色强调。使用内置风格时，颜色、字体和结构以当前主题为准；不要把纸张风格强加给主机、掌机或 iOS。所有主题都应有清晰的信息层级。

---

## 1. 控件：一律用 Lobe UI

我们已经装了 `@lobehub/ui`，它的控件自带统一的圆角、焦点、深浅色、动效和无障碍。自己拿原生元素拼，出来的就是「浏览器默认样式」，和整个站点脱节。

| 要做的事 | 用这个 | 不要用 |
| --- | --- | --- |
| 点击动作 | `Button`（文字操作）、`ActionIcon`（只有图标） | `<button>`、`<div onClick>` |
| 几个互斥的档位 | `Segmented` | 自己写的 tab 按钮 |
| 连续的值（音量、进度） | `Slider` | `<input type="range">` |
| 开关 | `Switch` | `<input type="checkbox">` |
| 下拉选择 | `Select` | `<select>` |
| 文本输入 | `Input`、`TextArea` | `<input>` `<textarea>` |
| 日期、时间 | `DatePicker`、`DatePicker.TimePicker` | `<input type="date">` `<input type="time">` |
| 小标签、状态 | `Tag` | 自己画的圆角 span |
| 悬停说明 | `Tooltip` | `title` 属性（只能当兜底） |
| 带表单的小浮层 | `Popover` | 自己写 absolute 定位的面板 |
| 进度 | `Progress` | 自己拼的 div 条 |
| 一个数字加它的说明 | `Statistic` | 自己拼 |
| 没有内容 | `Empty` | 一行灰字 |
| 加载中 | `Skeleton`、`Spin` | 文字「加载中…」 |
| 成组的内容块 | `Block`（可点的用 `clickable`） | 自己写边框和背景 |
| 弹窗 | `Modal` | 自己写遮罩 |
| 图标 | `@phosphor-icons/react`（默认 regular 粗细，需要更轻用 `weight="light"`）配 `Icon` / `ActionIcon`；Phosphor 是填充型图标，全局 CSS 已保证它在 Lobe 的 `Icon` 里正常着色 | emoji 当图标 |

只有在 Lobe 里**确实没有**对应物的结构上，才允许自己画：日历的日期格、环形或柱状的图形（SVG）、封面渐变。即便如此：
- 可点的格子必须能用键盘到达（`role`、`tabIndex`、Enter/Space），并有悬停、选中、聚焦三种状态；
- 颜色、间距、字号仍然只能用下面的 token。

## 2. Token：不写死任何值

**颜色**只用变量，深浅色自动适配：`--bg` `--bg2` `--bg3` `--text` `--text2` `--text3` `--text4` `--border` `--main`（红，强调）以及语义色 `--c-green` `--c-blue` `--c-amber` `--c-violet` `--c-red`。代码里出现 `#xxxxxx` 或 `rgb()` 就是错的（SVG 渐变封面这类生成的颜色例外，且要在深浅色下都看得清）。

**创建主题时**，配色值应写进主题数据：`overrides` 保存共用主色、圆角、外框等；`light` 和 `dark` 分别保存浅色与深色下的 `bg/bg2/bg3`、`text/text2/text3/text4`、`border/rule`，主色需要不同亮度时也分别写入。主题作者可以在这两套数据中定义颜色，组件仍只引用变量。新建完整风格必须照顾两种模式，不能把固定背景和文字颜色塞进一组共享变量，导致切换明暗后颜色不变。

`save_theme` 替换传入的整套分支，未传分支保留；`set_theme` 合并对应分支的补丁，`light: null` 或 `dark: null` 清掉对应分支。`set_theme` 的 `overrides: null` 清空全部共享变量、双模式覆盖和字体。`mode` 仅表示应用主题时的初始偏好，用户之后仍能切换。仅调整字体、圆角或外框可以不传两套配色；缺失的模式配色继承共享变量与系统基础色，不宣称它已有完整的定制设计。改完用 `list_themes` 核对两套数据，再分别检查浅色与深色的文字对比、层级与控件状态。没有实际看过时，明确只完成了数据检查。

**还原默认外观**之前用 `get_appearance` 查看默认资料、当前状态与差异。用户说「还原默认主题」「恢复默认外观」，用 `reset_appearance({scope: "all"})` 恢复纸张主题、默认字体与外框、纸质卡片 Dock，清理各页壁纸、特效图层、页面 CSS 和组件外观覆盖，并恢复首页默认背景。默认保留用户当前的明暗；明确指定浅色或深色时才传 `mode`。只还原首页背景或装饰用 `scope: "home"`，不改全局主题、Dock 和其他页面。页面内容、组件顺序、宽度、配置、对齐和业务数据都保留，主题库和模板库也保留；不要通过恢复布局、套用模板或删除组件来模拟还原外观。操作后再次读取 `get_appearance` 核对。

用户只想「切到纸张配色」时使用 `apply_theme({ref: "default"})`，它只切换配色与字体，保留已有壁纸、特效等装饰。默认配色、背景和样式的具体数值以 `get_appearance` 返回的资料为准。

独立特效组件、自编 App 和小程序的配置及源码属于页面内容，还原外观时保留。`get_appearance` 会在 `embeddedVisuals` 列出它们；还原后若仍有视觉差异，先检查这些组件的配置或源码，再按用户要求调整，不要声称所有自定义视觉都已消失。

**强调色的用量**：一个组件里红色只给一个东西——当前焦点（正在进行的计时、今天、正在播放的曲目）。其余用墨色和灰。红色用多了就等于没有重点。

**间距**只用 4 的倍数：4、8、12、16、24、32、48。组件内部分组之间 16 或 24，组内元素之间 8 或 12。

**字号**只用这几档：11（极小标注）、12（辅助）、13（列表正文）、14（正文）、18（小标题）、24（大标题）、40、64（焦点数字）。
**字体**：数字、标题、日期用衬线（`var(--font-serif)`），正文和控件用无衬线（Lobe 默认）。表示时间或数量的数字加 `font-variant-numeric: tabular-nums`，避免跳动。

**圆角**：本站是「编辑部」风格——方角、发丝线、不用渐变和毛玻璃。圆角一律读主题变量 `--radius` / `--radius-lg`（现在都是 0），不自定义像素。封面、色块用平涂或极轻的同色相两段色，不用炫彩渐变。

**边线**：1px `var(--border)`；强调的分隔用 `var(--rule)`（墨色）。不用阴影堆层次；阴影只给浮起的东西（弹层、dock）。

### 主机主题（Switch）

用户要求 Switch / 主机风格时，调用 `apply_theme({ref: "switch"})`。浅色、深色通过 `set_theme({mode: "light"})` / `set_theme({mode: "dark"})` 切换；这只改模式，保留主机外壳。`set_theme` 改内置主题的配色或字体会另存为普通自定义主题，不能把它当作保留主机布局的调色方式。不要为主机风格创建重复主题、注入整页 CSS 或重造导航。

- **宿主结构**：主屏顶部为头像与真实状态，中间为页面和已启用 Dock 的 AI 应用的方形封面，底部第一个红色圆钮使用搭搭 Logo 打开助手，其后为市场、已安装的监控和设置入口及操作条。系统导航由宿主管理，`set_dock` 不控制这些入口，`set_statusbar` 不替换主屏的真实状态区。头像使用 Boring Avatars，根据已保存的随机种子生成；可在个人设置「换一个」，刷新、改称呼或切换明暗保持头像。页面封面来自现有页面名称和图标；保留用户内容，不填充假游戏、虚构通知或电量。内容页、设置页使用紧凑操作条，避免圆菜单挤占内容。
- **设置结构**：顶部统一「设置」标题，左侧分类，右侧分组列表；窄容器一次显示分类或详情。复用现有 `Group` / `Row` / Lobe 控件，保留标签、说明、错误状态与可键盘操作的输入。焦点框只画一层：文本输入由整行承担外框，行内按钮、开关等独立控件使用自身焦点，不同时框住外层与内层。
- **色彩**：浅色灰底、深色炭灰底均由主题数据提供。内容使用 `--bg` / `--bg2` / `--bg3` 和 `--text` / `--text2` / `--text3`；强调文字使用 `--main`，焦点外框使用 `--switch-focus`。不可在组件中固定白底、黑字。圆形入口的语义色和封面色属于主机主题数据，不替代普通内容的语义变量。
- **形状与字体**：无衬线字体，方形封面、矩形列表、细分隔线。读取 `--radius` / `--radius-lg`，不添加大圆角、渐变、玻璃效果或厚阴影。只有系统头像和快捷入口为圆形。
- **内容页面**：页面标题 20–22px，分组标题 18px，列表正文 14–15px；面板内边距 16–24px。集合组件的外壳透明，由榜单、文章、书签分组各自提供矩形底色，避免把所有内容塞进一个无留白的大色块。完整保留热榜标题，热度与来源用次级文字。宽度按 `switch-widget` 实际容器响应，打开 AI 分栏后也要收拢列数；长内容使用整页滚动，底部操作条前留足空间。直接复用内置组件即可继承这些规则；自定义组件使用语义控件、主题变量与清晰的可访问名称，不依赖随机 CSS 类名。
- **交互**：封面先选中、再次点击打开，方向键移动焦点，Enter / Space 打开；原生 Tab 焦点保持可达。快捷键只在对应区域生效，不截获表单或 AI 输入。长名称可截断但保留可访问名称。触摸与滚轮可以横向浏览。
- **验证**：分别检查亮暗主屏、设置、内容页，以及手机、矮横屏和 AI 分栏的实际容器；底部操作不遮住内容，选中外框不被裁切。`inspect_page` 的有限 DOM 报告不能代替截图视觉检查。

### Windows 98 主题

用户要求 Win98 / Windows 98 / 经典 Windows 桌面时，调用 `apply_theme({ref: "win98"})`，不要自己创建一份近似配色或重复桌面。浅色为经典青绿桌面、灰色窗口和蓝色标题栏；深色保留同样结构，使用较暗的桌面、面板与输入区。通过 `set_theme({mode: "light" | "dark"})` 切换；修改内置主题的颜色、字体字段会另存为普通自定义主题并失去外壳。

- **桌面与窗口**：桌面展示主页、已显示页面与已固定 AI 应用；开始菜单可访问所有真实页面与应用，同时提供搭搭、组件市场、控制面板和已安装的监控。鼠标选中、双击打开，键盘 Enter 打开，触屏直接打开；不要编造我的电脑、回收站、磁盘容量等不可用功能。搭搭使用项目 Logo。
- **任务栏**：开始菜单、当前窗口任务、显示桌面、模式切换和真实时钟由宿主管理。窗口可最小化、恢复、最大化和关闭；普通页面复用当前窗口，最小化保留挂载与输入状态。AI 应用继续遵循自身的打开方式，独立窗口可拖动并为任务栏留出空间；不要声称所有普通页面都能拖动或任意调整尺寸。
- **样式**：方角、两层明暗边构成立体凸起按钮与凹陷输入框，标题栏可使用经典蓝色横向渐变。正文保留可读中文字号，不用像素字体降低长文可读性。语义变量控制内容色彩，`--win98-*` 控制桌面、窗口与选择状态；不能把浅色白底固定到深色模式。
- **焦点与布局**：独立控件保留清晰焦点，避免输入框与外层行同时套框。长内容整页滚动，实际窄窗口和 AI 分栏按容器排版，底部任务栏不能遮住最后一项。设置仍使用现有分类、分组与输入标签。
- **原有配置**：`set_dock` 不修改 Win98 任务栏。原壁纸与特效配置保留，Win98 桌面使用自己的纯色背景；切回其他主题后原配置继续生效。窗口里的状态条继续使用已配置的状态项。

**主操作按钮**：给 Lobe `Button type="primary"` 加 `className="ink-button"`，获得当前主题的主操作样式；Win98 会显示为立体按钮，其他主题遵循其配色。一个组件里只放一个主操作。

## 3. 版式：先定焦点，再排其余

每个组件先回答一个问题：**用户一眼该看到什么？** 那个东西就是焦点，给它最大的字号（40 或 64，衬线）；其余信息按「主信息（14）→ 辅助（12，`--text3`）」两级排，不要出现三个同样重要的东西。

三种组件形态，别混用：

1. **卡片型**：放进栅格，和别的组件并排（待办、倒数日、日程）。宽度由页面决定，不写死像素，半宽也不能溢出。
2. **舞台型**：独占一个页面的主角（番茄钟、音乐）。**必须在页面里水平、垂直都居中**，内容宽度有上限（窄的 ≤ 420px，宽的 ≤ 880px），四周留白。在 `registerComponent` 里声明 `stage: {width: 420}`，页面渲染器负责居中；组件自己不要再写居中的 hack。
3. **状态条型**：顶栏里的一小段，单行、很窄，自己更新。

番茄钟使用宽舞台（880px）：实际组件宽度达到 680px 时，左侧放模式与表盘，右侧放本轮任务、操作和统计；窄组件恢复单列。计时和暂停期间任务只读，布局不因输入框消失而跳动。响应条件来自组件容器，不能用整窗宽度判断 AI 分栏后的布局。

对齐：同一容器里所有内容共用一条左边线；数字右对齐用等宽数字；图标和文字的基线对齐。

没有指定页面分区、且页面只有一个已声明 `stage` 的组件时，由宿主居中展示；多个组件时，先放最重要的，再放辅助的，不要让每个组件都一样大。

### 页面分区

需要主视觉、内容集合或主辅关系时，先用 `list_page_layouts` 读取布局目录，再用 `get_workspace` 获取现有组件 ID。明确要求立即调整的单次编辑可用 `set_page_sections`；首页改版、试方案或预览使用下方草稿流程。分区只组织已有组件，组件的配置和应用身份继续保留。

| 结构 | 适用内容 | 参数与窄容器行为 |
| --- | --- | --- |
| `hero` 主视觉 | 一处标题、搜索或主要内容 | `items` 引用组件；`align: start/center`；最多一个主视觉，逐项满行 |
| `section` 内容分区 | 同类内容、快捷入口或信息集合 | `items` 与 `columns: 1/2/3`，默认2列 |
| `split` 主次分栏 | 主内容配日程、摘要等辅助信息 | `primary`、`secondary`；`ratio: equal/wide-primary`，默认2:1；主栏先读、辅栏后读 |

页面最多8个分区，每区有稳定 `id` 和可选 `title`；仅在标题有助于识别内容时填写，不添加口号或重复组件标题。ID 用1–48位字母、数字、下划线或短横线，标题最多80字。每个组件只能引用一次，不能引用其他页面的组件。分区没有额外的卡片底色、圆角或上边框，按留白与标题层级区分。

实际内容容器小于720px时，所有结构按阅读顺序叠成单列；桌面宽窗口中的窄AI分栏也按此处理。主次分栏的左右同一序号内容按行对齐，不能假定是独立的两列瀑布流。长标题可换行，长页面整体纵向滚动。现有组件仍需自己适配其实际宽度、空数据和操作状态。

例如已读取本页真实ID后，可以提交：

```json
{"pageId":"home","sections":[
  {"id":"welcome","kind":"hero","items":["当前时钟ID","当前搜索ID"],"align":"center"},
  {"id":"work","kind":"split","title":"今日","primary":["当前便签ID"],"secondary":["当前日程ID"],"ratio":"wide-primary"},
  {"id":"quick","kind":"section","items":["当前快捷入口ID"],"columns":1}
]}
```

上例组件ID是占位，调用时必须换成 `get_workspace` 的本页真实ID。未分组组件会追加到末尾；空分区不产生标题或空框。分区顺序、区内顺序以及主栏→辅栏决定阅读和键盘顺序，并同步为组件列表顺序。

`move_component` 与带 `index` 的 `add_component` 按此有效顺序定位：插入目标位置组件的分区/槽位之前，末尾进入未分组区；跨页默认追加到目标未分组区。应用只在同页修改宽度时保留所在分区。`sections: null` 或 `[]` 清除分区布局，保留当前组件顺序、宽度与数据；恢复上一次设计用撤销。创建后用 `get_workspace` 核对结构，再用 `inspect_page` 复查当前实际容器；它仍不代替审美检查。

### 首页组合与布局预览

首页改版优先 `get_workspace` → `list_homepage_recipes` → `create_homepage_draft`。四类方向围绕已有内容编排：

| 方向 | 内容层级 |
| --- | --- |
| `minimal` 极简启动 | 时钟、搜索居中作为主视觉，快捷入口和其余内容单列 |
| `productivity` 效率工作台 | 搜索优先，主要工作内容与辅助信息分栏 |
| `editorial` 编辑式内容 | 阅读内容优先、左对齐，快捷操作与信息放辅栏 |
| `showcase` 视觉展示 | 已有视觉内容或指定内容作焦点，其余内容两列 |

`focusId` 可明确指定首页已有组件作为焦点。组合只调整首页分区和顺序；不从其他页搬内容，不安装待办/日程，不创建假记录，也不重建应用或改写主题、背景和组件配置。内容不足时省略空区；空首页保持空态，不用口号或空卡片填满。新增内容或修改外观仍需独立明确的操作。

创建后预览自动出现，也可通过命令面板「预览首页方案」进入。草稿只在当前会话内存中，刷新后丢弃；已有草稿不会被另一条创建请求静默覆盖。用 `get_homepage_draft` 读取 `draftId`、`revision` 和实际结构，`update_homepage_draft` 携带对应 `expectedRevision`，传新的 `sections` 或重新选择 `recipeId`，两种修改不能混在同一次请求中。省略分区不代表清空，显式 `null` / `[]` 才清除分区。

预览复用真实布局和当前主题，但不运行第二份应用、取数或读写私有业务数据。时钟、搜索、快捷入口和文字效果使用配置的静态表示，其他组件显示类型占位；壁纸、动画、实时数据及应用内部行为不在预览范围。界面应简短说明这层限制，避免用户把占位当成已完成的小工具。

用 `inspect_homepage_draft({draftId})` 检查当前可见草稿，再通过草稿工具修正、复查。报告必须核对 `target`、草稿版本、实际容器与主题，并保留静态/占位的未知项。正式 `inspect_page` 与草稿检查分开；预览阶段不要用 `set_page_sections`、`apply_template` 等正式工具代替草稿更新。

用户确认方案后，调用 `apply_homepage_draft` 并带最新版本，或由用户点击「应用」。它只提交一次，可整体撤销；取消使用 `discard_homepage_draft`，不会写入正式页面或历史。若首页在草稿创建后已变更，应用会拒绝覆盖并保留草稿，需重新基于当前首页生成；其他页面或全局明暗的修改会保留。几何问题清空不代表审美、照片对比度或完整应用体验已通过。

## 4. 状态：每个交互元素都要想完

悬停、按下、聚焦（键盘可见的焦点环）、选中、禁用，以及整个组件的**空、加载、出错**三种状态。

- 空状态用 `Empty`：一句话说清「这里是什么」加一句「怎么开始」，不要只有一个空框。
- 出错要说人话和下一步（「这个地址播不了：可能已失效」，而不是「Error」）。
- 加载用骨架或保留上一次的数据，不要让布局跳动。

## 5. 动效

界面过渡只做有意义的：状态变化、焦点数字更新。时长 100–200ms，缓动用 ease；优先只动 `transform` 和 `opacity`。持续背景与图形特效单独按下面的规则选择。所有持续动画（均衡器、呼吸）必须尊重 `prefers-reduced-motion`。

### 特效选择与适配

先安排内容主次，再决定是否需要装饰。默认一个主要视觉效果即可；阅读、搜索、记录等信息密集页面优先静态或低干扰背景，不默认同时叠动态背景、动态标题和光效卡片。只有用户明确需要 3D 时才使用 Spline。

使用 `list_effects` 查已注册效果和参数；不因为安装了某个库就假定 AI 可以直接使用其全部组件。图层和内容块共同计量：同页最多8个成本点、1个GPU效果、3个持续动画；DOM/SVG为1点、Canvas为2点、WebGL为3点、Spline为6点。点数是产品约束，不是实测帧率。图层仍最多三个，不能通过改用内容块绕过预算。`list_effects` 的 `policy` 披露真实渲染方式、容器/触屏/减少动画策略、质量限制与来源；`get_workspace` 的 `effects` 返回页面预算和桌面/窄容器降级清单。

- 按实际容器适配手机、抽屉、小组件与 AI 分栏。小于480px时运行预算降为4点、不运行GPU；WebGL/Spline与光效卡片显示静态替代，文字保留完整内容。粗指针关闭跟随装饰、光效卡片与点击火花，悬停触发的文字改为入场。长标题允许换行，触屏必须能直接读到信息。
- 普通控件沿用主题变量。特效可传 `params.palette: "theme"` 使用宿主语义色板，也可在 `params.light` / `params.dark` 中分别设置当前效果的颜色字段。具体字段见 `list_effects` 的 `theme.colorFields`；分支仅接受颜色或颜色数组，不接受动画、布局、scene等参数。覆盖顺序是普通参数→语义色板→当前模式分支；无新配色字段时保留旧固定色与已有适配。颜色值使用合法具体色值，不能直接传 `var(...)`；宿主负责把语义色解析为渲染器可用颜色，切换明暗或在同模式下修改主题都会更新。
- 例如文字特效可用 `params: {palette: "theme", light: {color: "#24201c"}, dark: {color: "#eee8df"}}`；背景颜色字段可能是lineColor、colorStops等，不照抄文字的color。更新组件时params按键合并，light/dark各分支整体替换；传 `palette: null` 关闭语义色板，`light: null` / `dark: null` 清除对应分支。只改字号、动画不会清除配色。Spline只能调整宿主横幅文字，不能调整远程场景；Noise无可配颜色。
- 写自定义动画时实现减少动画的静态结果、离屏/页面隐藏暂停与销毁清理。选择现有效果时，只依据目录明确披露的信息判断；应用内 AI 不能读取 vendor 源码，目录未说明的能力视为未知，不能声称已核对，也不能仅通过降低速度声称已经支持减少动画。
- 关键标题、正文和操作不能只靠动画表达。减少动画、离屏、页面隐藏及预算降级时，宿主卸载装饰渲染器，保留静态文字、卡片正文或背景替代；错误隔离和懒加载也保留这些内容。文字与卡片静态态沿用解析后的配色。WebGL不可用、已识别的着色器初始化失败、图形上下文丢失或组件加载失败会给出说明和重试；图层通过页面「特效已简化」入口重试，内容块可直接重试。浏览器缓存模块下载失败时可能需要刷新。切换效果配置也可重置失败，主题切换和装饰重试不重挂业务页面。静态背景是安全替代，不是原效果截图；不承诺捕获第三方任意异步异常，也不自动修正显式配色的对比度。

- 添加、更新、移动、模板应用和还原默认外观都会检查预算。旧超限页面可读取、普通编辑和逐步减负，不能继续增加超限维度；导入、迁移、撤销保留配置，运行时按图层→内容块的顺序选择可运行效果，其余静态显示。「特效已简化」可查看原因。运行降级与质量上限不改写保存参数。还原默认背景若与已有特效块冲突，先减少效果或移动相关块，再重试还原，不擅自删除内容。
- 预算覆盖已注册的页面特效，不计量HTML App / Applet源码内的任意动画。历史素材若缺少对应上游版本和许可凭据，按目录标记待核对，不声称已完成许可验证。
- 当前应用内 AI 可用 `inspect_page` 测当前已挂载页面的有限 DOM 几何，但没有截图反馈。没有实际测量的手机尺寸、对比度、视觉效果或性能不得宣称已经验证。

## 6. 无障碍

- 只有图标的控件必须有 `title` 或 `aria-label`，并配 `Tooltip`。
- 文字与背景对比度至少 4.5:1；`--text3` 只用于辅助信息，不用于需要读的内容。
- 所有操作都能只用键盘完成。
- 不用颜色作为唯一的信息载体（休/班用字，不只靠红灰）。

## 7. 文案

中文，短，动词开头（「添加」「开始」「换一句」）。不用感叹号，不用「请」。数字和单位之间不留空格以外的东西（「25 分钟」）。

应用内的文案只保留任务所需信息，不放口号、重复标题和显而易见的操作说明。列表不使用大圆角卡片、色块容器或逐行上边框，靠对齐和间距区分项目。市场与管理列表只保留名称、必要简介和操作；分组集中在筛选栏显示，不重复展示打开方式或安装提示。

## 8. AI 造的东西：选对档位

有交互的小工具，**首选小程序（`create_applet`）**：逻辑是 AI 写的 JavaScript，界面只能用积木目录里的 Lobe 控件拼，由主页真实渲染。控件沿用主页风格、深浅色和键盘交互，AI 不用也不能写 CSS；作者仍需给操作提供名称，并设计布局和状态反馈。写法与完整创建参数示例见技能 `applet`（积木目录由 `src/lib/applet/catalog.ts` 生成，和实现同源）。

只有这几类才用沙盒应用（`create_app`，iframe）：游戏、Canvas / WebGL / Three.js、需要完全自定义视觉的东西。它必须**模仿**同一套规范：
- 颜色、字体只用主页注入的变量（`--bg` `--text` `--text2` `--text3` `--border` `--main`、`--font-serif`、`--font-sans`）；
- 按钮、输入框、开关自己写时，要有 1px 边线、聚焦环、悬停态，尺寸和 Lobe 的 `middle` 一致（高 32px，字号 14）；
- 沙盒里没有 `localStorage`，存数据用 `tada.store`；复制用 `tada.copy`；
- 背景透明，圆角用 `--radius` / `--radius-lg`；内置 `.btn.primary` 为墨色主操作，`.row` 可换行，`.grid` 按容器自动收列，宽表放入 `.table-wrap`；
- 主题变化会热更新变量和 `tada.dark`，不会重启应用；Canvas 等手绘内容可监听 `window` 的 `tada:themechange` 事件，读取 `event.detail.dark` 重新绘制；
- 同样遵守第 2、3、4、5、6 节。

声明式组件（`create_widget`）直接使用已有的列表、卡片、数字、插图样式，不另写 CSS。

### 应用目录、形态与设置

`create_applet` / `create_app` 默认安装进组件市场的应用目录，不自动创建页面或固定 Dock。创建时 `pageId` 可选，只有用户需要页面小组件时才提供。一个应用保留同一 ID、源码与私有数据，最多挂载一个页面；`mount_application` 的 `pageId: null` 仅取消挂载。编辑前用 `list_applications` 读取目录记录与源码，分组用 `group`，常用入口用 `dock` / `status` 按需开启，管理配置用 `configure_application`。

默认打开方式由 `openMode` 指定为 `modal`、`drawer` 或 `page`，用户在应用设置中选择。桌面 `modal` 由宿主提供交通灯、可拖动标题栏、最小化及最大化／还原；移动端保留标题与关闭按钮。应用内容不要重复绘制这些控件或打开方式选项卡。最小化仅隐藏主窗口，不卸载运行实例，页面和状态栏的同 ID 视图仍暂停；从画布底部入口或组件市场恢复会保留运行状态。运行时 App 读 `tada.surface`，Applet 读 `ctx.surface`，共五种形态：

| surface | 所处容器 | 布局要求 |
| --- | --- | --- |
| `widget` | 页面小组件，宽度由页面与 span 决定 | 半宽也能使用，不假定占满屏幕 |
| `modal` | 弹窗 | 按弹窗内容宽度布局，长内容允许纵向滚动 |
| `drawer` | 抽屉 | 窄容器优先纵排，手机不横向溢出 |
| `page` | 应用全页面 | 仍按实际内容容器宽度布局 |
| `status` | 顶部紧凑视图 | 单行、限高 32px，只留数字、图标或核心状态 |

布局必须依据实际容器宽度，弹窗、抽屉、小组件都不是全浏览器窗口。Applet 的 `ctx.viewport = {width, compact}` 提供可见内容宽度，`compact` 表示容器小于 480px，与 `surface === "status"` 含义不同。`Grid` 测量自身容器并自动减少列数，`minColumnWidth` 默认 180px（可设 80–600）；只有计算器键盘等固定网格才用 `responsive: false`。`Stack` 最大宽度不超过容器，横排默认换行，`wrap: false` 保留强制同行；窄表单可改 `column`。HTML App 使用 iframe 内响应式 CSS，避免固定宽度和 `100vw`，表单和长标签在窄容器换行。

状态栏默认 `statusMode: "launcher"` 只显示启动按钮。需要真实状态视图时，先在源码实现 `surface === "status"` 分支，再启用 `status: true, statusMode: "compact"`。Applet 桌面最大宽 200px、手机 140px；HTML App 桌面宽 160px、手机 130px，两者限高均为 32px。不要把完整窗口的标题、表单、大按钮直接塞入状态栏。

主窗口或可见页面小组件运行时，宿主暂停同一应用的紧凑视图并回退启动按钮，避免并发写入。切换形态可能重新挂载，只有显式持久化的业务数据会保留。关闭主窗口后，若紧凑状态栏仍挂载，则继续运行该形态；所有运行形态卸载后没有后台常驻定时器、轮询或通知。倒计时保存截止时间，重新打开后按当前时间计算。

可配置项使用 `settingsSchema` 声明，`settings` 保存当前值；系统在「设置 → 应用」生成表单，例如：

```json
{"settingsSchema":{"minutes":{"kind":"number","label":"专注分钟","default":25,"min":1,"max":120}},"settings":{"minutes":30}}
```

字段支持 `string`、`number`、`boolean`、`select`；选项字段提供 `options: [{value, label}]`。App 通过只读 `tada.settings` 读取，修改设置后宿主安全重载应用，`tada.store` 保留。Applet 通过只读 `ctx.settings` 读取，设置变化更新上下文并重渲，保留 `persist` 状态；`init` 只在启动时执行，`onSettingsChange(s, ctx, previous)` 在初始 `init` 完成后仅针对实际设置变化调用，`previous` 为改变前的只读设置。定时器、数据源等副作用应在此取消旧任务再重新设置，不放入 `view`；尺寸变化只调整布局。

设置与业务状态分开，后者用 `tada.store` 或 Applet 的 `persist`。打开设置用 `open_settings` 的 `section: "application:<id>"`。卸载使用 `uninstall_application`，移除目录与入口但保留本机私有数据，支持撤销。

业务数据由独立 IndexedDB 应用仓保存，每个实例的整个 JSON 对象最多 8 MiB（UTF-8 字节）；浏览器实际配额另行约束。仅保存合法 JSON 值。App 的 `tada.store.get/set` 都需处理 Promise 失败，`set` 事务提交后才成功，不能把读取失败当作空值后覆盖。Applet 用 `persist` 声明业务字段，读取成功后才执行 `init`，宿主显示保存中、失败和重试；不要在事件处理完就自行提示已保存。切换形态、设置重载或卸载不会删除已经接受的业务数据，刷新前应等待保存完成。配置同步不包含业务数据，完整同步和完整备份包含。

### Applet 趋势与数据图表

简单非负柱状比较继续用 `ui.Bars`；连续记录的趋势用 `ui.LineChart`。具体属性和可执行记录工具示例从 `use_skill applet` 的真实目录读取，不在 Applet 中导入外部 React 图表组件。

折线输入为有序 `labels` 与 `series: [{name, values, tone?}]`，共同使用一个单位和纵轴。先按日、周或月整理数据，最多120个标签、4个系列；超出时明确聚合方式，不能偷偷截掉旧数据再称为全部趋势。分类横轴按输入顺序等距展示，不会自动按日期间隔缩放或排序。

`null` 表示缺失，会断线；零和负数都是有效值。不要用0填补未知记录，也不要把请求失败交给空图掩盖：加载和取数错误由应用明确呈现。图表对不匹配长度、错误类型、非有限值或超限数据给出局部错误；数值绝对值上限为1e12。

主题颜色由宿主token映射，系列还用线型区分。刻度根据实际容器宽度减少，完整标签与准确数值在“查看数据”的明细中；触摸和键盘都应能打开。状态栏仅给最新值或简短状态，不塞完整图表。尺寸和主题变化只更新视图，不重新请求、重启定时器或清空记录。

### Applet 记录与数据管理

少量静态数据继续用 `ui.Table`；需要搜索、排序、分页、选择或详情的记录工具用 `ui.DataTable`。具体属性与可执行示例从 `use_skill applet` 读取，列只传纯数据，不导入外部React表格或传入列内render函数。

每条记录使用稳定业务ID，不能用当前页/排序后的下标。提供 `state` 和顶层 `onChange`，将回传的局部patch合并进视图状态（`Object.assign(s.table, patch)`）；记录和必要ID计数用persist，搜索词、页码、排序与选择默认是临时状态。业务数据、用户设置和显示状态保持分开。

搜索会匹配全部列，包括窄屏隐藏字段；数字列显式指定number，避免把10排在2前面。选择可跨页保留，“全选当前页”只影响当前页，批量操作依据ID，不能用页面行号删除。空数据、搜索无匹配和取数失败要区分，表格不负责网络请求。

最多500行、8列、每段文本500字符；非法/超量会明确报错，不悄悄截断。App / Applet 每个实例的业务 JSON 总量最多 8 MiB，按 UTF-8 字节计；应根据实际文本量限制记录，示例的100条记录限额不是全部应用可无限扩容的承诺。

按实际容器显示优先字段，手机与窄抽屉通过“详情”读取完整值；分页、排序、搜索、选择和详情都应可由键盘和触摸操作。状态栏只返回记录数或简短摘要，尺寸/主题变化不能清空输入、重启应用或重复取数。

## 9. 交付前自检

1. 宿主页面或 Applet 有没有自行拼接原生 button / input / select / range？有就换成 Lobe 或目录中的积木；HTML App 的自定义控件按本规范适配。
2. 有没有写死的颜色、像素字号、奇怪的间距？
3. 焦点是什么？是不是最大、最显眼的那个？红色是不是只出现了一处？
4. 舞台型组件是否按宿主居中？是否按实际开启的形态适配了 320–375px 手机、半宽小组件、弹窗、抽屉和状态栏尺寸？
5. 空、加载、出错、禁用、聚焦反馈是否完整？
6. 浅色和深色的变量、对比度是否都已核对？
7. 只用键盘能不能完成所有操作？
8. 应用设置是否确实被逻辑使用，修改后相关定时器与数据源是否更新？生成后用 `list_applications` 核对源码、设置、分组、入口，再按用户需要 `open_application`。

页面修改后可用 `inspect_page` 获取当前实际挂载页面的容器与内容尺寸、主题、减少动画、版本和检查时间，以及可定位到组件的横向溢出、明显裁切或零尺寸问题。修改后再次调用，核对同一问题是否消失。默认检查当前页；显式传其他页面 ID 不会自动打开它。AI 分栏缩窄页面后，报告使用左侧实际容器宽度。

`status: "ok"` 只表示取得了这次 DOM 采样；`issues: []` 不代表视觉验收通过。隐藏、未挂载、没有布局盒、等待超时或工作空间与 DOM 尚不同步会明确返回 `unknown` / `unavailable` 或未知项。iframe 与 Canvas 只测外框，内部内容、文字对比度、审美和完整无障碍始终需要其他验证。合法的组件内滚动和表格横滚不作为页面溢出错误。

检查器不读取截图、聊天、页面正文、表单值、iframe 文档或 Canvas 像素，也不导航、不修改工作空间或撤销历史。特效列表仅反映页面根节点内的宿主运行标记，不代表实测帧率、成功绘制或完整背景图层检查。

代码开发时，有浏览器工具就实际检查各宽度和模式，并说明检查范围。应用内 AI 没有浏览器截图反馈；有限 DOM 测量、源码配置核对和打开应用，都不能声称已完成浏览器视觉验收。
