# 功能修复计划

记录日期：2026-10-26。范围是修复已存在但未接通或行为错误的功能；数据连接器、阅读收藏库、任务系统和个人应用库另行规划。

## 已确认的线上根因

`https://dada.tulai.design/__proxy?url=https%3A%2F%2Fhnrss.org%2Ffrontpage` 在无条件请求时返回 `200 text/html`，正文是搭搭首页；带该响应的 ETag 条件请求时返回 `304`。RSS 源和热榜上游接口分别能正常返回 XML 和 JSON。

应用默认使用 `/__proxy?url={url}`，但原 Docker 镜像只运行 Nginx，未部署这条代理。请求落入 SPA 的 `try_files … /index.html`，所以 304 是首页的缓存校验结果，并非订阅源没有更新。禁用缓存不能替代补齐代理。

## 第一阶段：恢复生产取数

- [x] 镜像内置无状态的同源取数代理，保留 Nginx、现有域名、端口和 `/__proxy` 地址；不依赖公共第三方转发服务。
- [x] 为 `/__proxy` 单独路由，返回上游原始正文、状态和 Content-Type，错误返回明确非 2xx；所有代理响应 `no-store`，不回退首页。
- [x] 限制目标协议、目标地址、重定向、请求时长和响应大小；拦截私网及回环地址，不转发浏览器 Cookie。
- [x] 监督代理和 Nginx 两个进程，任一异常都能退出或体现为健康检查失败。
- [x] RSS / 热榜检测 HTML 首页、错误格式和超时；RSS 全源失败时保留上次文章，部分失败仍可阅读成功的来源。

验收：构建后的容器中，Hacker News 返回 RSS，NewsHub 返回 JSON；缺少参数、错误目标和上游失败返回明确错误；已有默认代理配置可直接沿用，自定义代理和显式直连不被覆盖。

以下五项均已完成本地修复及验证，尚待发布上线。网络授权另补了「设置 → 网络」的逐域名撤销入口；AI 发送在初始化前加锁，避免慢存储下重复发起请求。

| 问题 | 修复内容 | 验收条件 |

## 本轮验证记录

- `pnpm test`：生产代理 8/8，热榜工具 8/8，以及助手发送锁、文章附加和授权队列回归。
- `tests/content-regressions.html`：真实浏览器 DOMParser 回归 20/20；内容解析、失败处理和文章上下文均有覆盖。
- 全量 `tsc --noEmit` 通过；Docker 完整生产构建（含 Vite / PWA）通过。
- 真容器内经 Nginx → Node 请求 Hacker News 返回 200 XML、NewsHub sources / batch 返回 200 JSON；带旧首页 ETag 的请求仍返回 200 正文。
- 容器的健康检查、Umami 配置、JSON 错误、内网拦截、限流及 Nginx 退出监督通过。临时验证容器已清理。
- 浏览器使用隔离端口与模拟 AI / 数据接口验证：点击文章提问时请求数为 0；用户发送及追问都带有文章资料；关闭重开保留草稿；域名等待和拒绝时不请求，允许后原 iframe 完成请求，设置中可撤销；两张静态卡片独立，编辑即时更新；页面 CSS 实际计算样式生效。
- 并发回归验证：同域名共享确认，旧弹窗重复回调不误授权下一域名；AI 初始化等待期间只发起一次请求，失败可释放发送锁。

本轮修复通过 `main` 分支交付，推送后自动触发 `Publish image` workflow 发布镜像；具体构建结果以 GitHub Actions 运行记录为准。线上仍需拉取新镜像并在 Coolify 重新部署，然后使用正式域名复查上述两个接口和页面取数。

## 部署边界

内置代理服务于 Docker / Coolify 部署。仅上传 `dist/` 的纯静态部署仍需单独部署自有代理。跨设备同步的 WebDAV / HTTP 使用各自的代理设置，不将本轮公共取数代理视为完整同步网关。
