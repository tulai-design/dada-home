## 记录与晋升

- `research/` 保留研究日期、问题、证据和结论；外部信息链接原始来源，代码判断链接真实文件。
- `milestones/` 记录阶段范围和任务之间的关系，不重复维护每个任务的验收勾选。
- 有正式发布工作时再创建 `releases/`，记录验证范围、提交和公开发布信息；不保存密钥、Cookie、私有连接信息或未经脱敏的用户数据。
- 稳定产品结论更新到 `product/`，可验证行为更新到 `specs/`，重要取舍记录到 `decisions/`，开发约束提炼到 `.trellis/spec/`。

历史记录可以保留当时结论，但应链接其后续替代文档。不能因为研究或计划完成，就把产品功能标记为已实现。
