# 搭搭 · tulai.design

> 陪你把想法，搭成自己的主页。

**搭搭**是一个亲切、有帮助的 AI 个人主页搭建助手，也是图来设计（[tulai.design](https://tulai.design)）的一颗新星。

你可以告诉搭搭“给我做一个安静的阅读主页”“把天气和待办放在一起”，它会通过内置工具创建页面、组合组件、调整主题和布局。你也可以自己动手细调，把满意的设计存成模板，再继续搭建自己的数字空间。

搭搭采用本地优先的数据存储，不依赖应用后端；AI 接口、联网搜索和跨设备同步由你选择和配置。

## 项目现状

当前版本已实现数据化页面、统一组件协议、AI 工具调用、主题与模板库，仍在持续完善功能和使用体验。

- **可组合的个人主页**：页面由组件实例组成，支持添加、移除、排序、尺寸与外观调整；组件可以声明自己的设置和数据。
- **阅读与信息**：RSS 订阅、阅读器与 AI 摘要、热榜、书签、天气、搜索和服务监控。
- **日常工作台**：待办、便签、日历、日程、倒计时、番茄钟和音乐；组件市场提供可安装的功能页面，部分组件独占页面时采用居中的舞台布局。
- **AI 搭建与操作**：通过自然语言编辑页面与组件、管理主题和模板、整理书签、操作站内数据；支持用户画像、助手性格与记忆，以及单独配置的联网搜索。
- **外观定制**：明暗主题、CSS 主题变量、Google Fonts、窗口外框、壁纸与特效图层，以及支持桌面和移动端的 Dock。主题和页面设计可以保存、切换与复用。
- **AI 自定义组件与应用**：支持声明式组件、小程序（Applet）与隔离沙盒应用；AI 应用可在组件市场中打开、分组、设置和卸载，按需添加 Dock、状态栏或页面小组件。
- **本地数据与跨设备使用**：localStorage + IndexedDB 存储、备份导入导出，以及可选的 WebDAV / GitHub Gist / 自建 HTTP 同步。
- **安装与部署**：支持 PWA，提供 Docker、Coolify 部署配置和 GitHub Actions 镜像发布工作流。

应用使用 React 19、TypeScript、Vite、Lobe UI 和 Phosphor Icons。页面内容由工作空间数据决定；`src/App.tsx` 负责应用外壳、共享数据和界面入口。

AI 能力需要用户配置接口和模型；RSS、监控、联网搜索、同步等外部服务也需要相应连接配置。浏览器书签扩展目前提供本地安装方式，上架材料已经准备，仓库中尚未配置商店安装地址。

## 开始使用

需要 Node.js、pnpm 和 `zip`（构建时用于打包浏览器扩展）。CI 使用 Node.js 22。

```bash
pnpm install
pnpm dev       # http://localhost:5173
pnpm test      # 代理、站内工具、主题、应用目录与运行时回归
pnpm build     # 打包浏览器扩展、类型检查并构建到 dist/
pnpm preview   # 本地预览生产构建
```

开发服务器和 Docker 镜像均提供 `/__proxy?url=…` 转发，用于请求受浏览器跨域限制的 RSS、热榜和公开监控接口。默认代理模板 `/__proxy?url={url}` 可直接使用。`pnpm preview` 和仅上传 `dist/` 的静态托管不运行代理，需要单独配置自有代理。

浏览器内容解析回归可在开发服务器中访问 `http://localhost:5173/tests/content-regressions.html`，使用真实 DOMParser 检查 RSS / Atom / RDF、错误代理响应及文章上下文，不修改用户数据。

## AI 助手

在「设置 → 搭搭 AI」填写 OpenAI 兼容服务的接口地址、模型和 API Key。助手通过流式 `chat/completions` 请求工作，支持 Markdown 回复、多轮对话和工具调用；页面搭建与站内操作需要模型支持工具调用。

AI 可以发现已注册的组件和可用操作，创建页面、编辑布局与配置、切换主题、保存模板，也可以管理订阅、待办、便签、日程和书签。工作空间修改经过参数校验并进入撤销历史；删除等高风险工具调用会按权限设置请求确认。助手内置的技能说明提供设计规范、组件与小程序的使用约定。

主题支持分别保存浅色和深色配色，切换明暗会使用对应的一套，圆角、字体和外框等设计可以共用。AI 创建完整主题时需要提供两套配色；旧主题只有一套时，保留原有模式的设计，另一模式使用系统基础配色。主题的初始明暗偏好不会阻止用户切换，刷新后保留最后选择；模板和备份也会保留两套配色。

可以让搭搭「恢复默认外观」：它会恢复纸张主题、默认字体与外框、玻璃 Dock 和首页默认背景，并清理各页额外的壁纸、背景特效图层、页面样式与组件外观。页面内容、组件顺序和布局、业务数据、已存主题和模板都会保留，当前明暗也保留，支持撤销。独立特效组件和自编应用也作为内容保留，助手会列出它们，方便继续检查。只想还原首页背景时可以直接说明；只切回纸张配色则会保留已有背景与装饰。助手可先读取默认外观与当前差异，再执行还原并核对结果。

自定义内容有三种主要方式：

| 方式 | 适用内容 | 实现方式 |
| --- | --- | --- |
| 声明式组件 | 列表、卡片、统计、链接、文字与 SVG 插图 | AI 描述数据源和显示规格，由现有渲染器呈现 |
| 小程序（Applet） | 计算器、换算、生成器等交互工具 | AI 编写 JavaScript 逻辑，在隔离沙盒中运行，界面由主页使用 Lobe 控件渲染 |
| 沙盒应用（App） | 游戏、Canvas / WebGL 或完全自定义的视觉内容 | AI 编写 HTML / CSS / JavaScript，在隔离 iframe 中运行 |

AI 创建的 App / Applet 默认安装到「组件市场 → 我的应用」，可以搜索、按分组查看、打开、进入设置或卸载。应用独立保存在工作空间的应用目录中，不要求拥有页面，也不会自动加入 Dock；旧页面中的应用会按原 ID 纳入目录，保留内容和私有数据。

应用支持弹窗、抽屉和全页面打开，可在应用设置中选择默认方式，也可在打开后切换。Dock 和顶部状态栏按需启用；页面小组件可选择挂载页面与宽度，取消挂载仍保留应用。状态栏既可显示启动按钮，也可运行应用提供的单行紧凑视图；源码需要明确适配 `surface: "status"`。同一应用的独立窗口、可见小组件和紧凑视图由宿主协调，避免同时运行多份逻辑改写同一份数据。

「设置 → 应用」会显示每个已安装 AI 应用的设置入口。AI 用 `settingsSchema` 声明字符串、数值、开关或选项字段后，系统生成设置表单；App 通过 `tada.settings` / `tada.surface`，Applet 通过 `ctx.settings` / `ctx.surface` 读取设置与当前形态。用户设置与应用业务数据分开保存。卸载移除应用、入口和页面小组件，保留本机私有数据，支持撤销找回。

自定义组件、App 和 Applet 访问新域名时会请求用户确认，拒绝后不发取数请求。允许后，等待中的 `tada.fetch` / `ctx.fetch` 可以继续；授权可在「设置 → 网络」撤销。App 的图片和媒体域名受文档 CSP 控制，新授权需要切换页面再返回，或修改应用源码后生效；撤销已有域名会立即重新生成文档并收紧权限。

阅读器中的「带着这篇文章去问」会先附上文章并打开提问草稿，等用户发送后才请求模型。会话保存文章标题、链接与订阅提供的正文或摘要，后续追问仍可使用；只有标题和链接的订阅不会被当作全文生成摘要。

联网搜索在「设置 → 联网搜索」单独配置，支持 Tavily、Firecrawl、SearXNG、Exa 和 Brave。助手还可以打开浏览器搜索结果页；打开搜索页与由助手读取搜索结果是两种不同的操作。

## 本地数据与备份

数据默认保存在当前浏览器、当前站点下：

| 存储 | 内容 |
| --- | --- |
| localStorage（`fp.` 前缀） | 工作空间结构、应用目录、主题与模板、设置、用户画像与记忆、已读记录，以及 App / Applet 私有数据等 |
| IndexedDB | 组件业务数据、会话与对话轮次 |

在「设置 → 数据」中可以导出或导入备份，备份涵盖两类存储。**导入备份会整体替换当前数据，并重新加载页面，不会与现有数据合并。** 模板则保存页面设计快照，可包含主题，不包含待办、便签等组件业务数据。

使用 AI、联网搜索、订阅、天气或监控等功能时，会向对应服务发送请求；开启同步后，所选数据会上传到你配置的存储。AI 服务的 API Key 等连接信息也保存在浏览器中，只应在可信设备上填写。隐私说明见 [隐私政策](public/privacy.html)。

### 跨设备同步

在「设置 → 同步」中选择 WebDAV、GitHub Gist 或自建 HTTP 接口，可以手动同步或开启自动同步，无需搭搭的应用后端。

- 同步文件按记录合并：一份配置、一份组件数据、一个会话或一轮问答分别作为记录；同一记录发生冲突时，以最后修改的版本为准，删除通过墓碑记录传播。这不是逐字段合并或实时协同编辑。
- 可以设置口令进行端到端加密；未设置口令时，普通数据不加密。
- API Key、监控 Token / 密码和 `.ics` 订阅地址默认不同步；开启「同步密钥」必须同时设置加密口令。
- 同步连接配置保留在各设备本地，需要分别配置。WebDAV / HTTP 服务需要支持相应的跨域访问与读写请求，或使用兼容的代理。

## 部署

### 静态站点

运行 `pnpm build` 后，将 `dist/` 部署到静态托管服务即可。应用本身无需后端；生产环境中的外部取数仍需要可用的跨域接口或独立代理。

### Docker 与 Coolify

仓库提供的 Compose 配置使用 `ghcr.io/tulai-design/dada-home:latest` 镜像，默认映射到本机 8080 端口：

```bash
docker compose up -d
```

也可以使用仓库中的 Dockerfile 自行构建：

```bash
docker build -t dada-home .
docker run -d --name dada-home -p 8080:80 dada-home
```

Coolify 部署使用 [docker-compose.coolify.yml](docker-compose.coolify.yml)，在服务上配置域名与 HTTPS。镜像内由 Nginx 托管静态页面，Node 提供同源取数代理，`/healthz` 同时验证代理进程；任一进程退出都会结束容器，交给部署平台重启。GitHub Actions 已配置类型检查、前端构建、代理回归测试、容器冒烟测试，以及向 GHCR 发布 amd64 / arm64 镜像的工作流。

容器可通过 `UMAMI_WEBSITE_ID`、`UMAMI_SRC`、`UMAMI_DOMAINS` 配置可选的 Umami 访问统计；未设置网站 ID 时不加载统计脚本，用户也可以在设置中关闭统计。

### 生产取数代理

**Docker / Coolify** 默认内置 `/__proxy`，更新镜像并重新部署后即可沿用默认代理地址，无需额外部署 Worker。该路径单独转发至代理服务，返回上游原始正文、状态与 Content-Type，响应不缓存；错误不会落入首页 HTML。

内置代理仅支持公共 HTTP(S) 标准端口的 GET 请求，限制连接时长、响应大小和并发，并校验 DNS 解析结果及每次重定向，拒绝私网、回环和云元数据地址，不转发浏览器 Cookie。可设置 `PROXY_ALLOWED_HOSTS=hnrss.org,newshub.shenzjd.com`，限制允许的目标域名（含其子域名）；留空时允许公共域名，仍禁止私网。WebDAV / HTTP 同步需要写入方法，应使用各自独立的同步代理。

**纯静态托管 / 本地生产预览** 可使用自有代理。仓库提供了独立的 [Cloudflare Worker](worker/proxy.ts)：

```bash
npx wrangler deploy worker/proxy.ts --name tada-proxy
```

部署后，在「设置 → 网络 → 自定义 → 代理模板」中填入：

```text
https://tada-proxy.<你的账号>.workers.dev/?url={url}
```

建议在 `worker/proxy.ts` 的 `ALLOW_HOSTS` 中列出需要访问的域名，限制代理目标范围。

若订阅或热榜提示代理返回了网页 HTML，先检查代理地址是否落入静态站点的首页回退。`304` 可能只是该首页的缓存校验结果，不能说明 RSS 已成功取回。此次问题的范围、验收条件和进展见 [功能修复计划](docs/fix-plan.md)。

### PWA

生产环境会注册 Service Worker，可通过支持 PWA 的浏览器安装到桌面或主屏幕；部署时使用 HTTPS（本地 localhost 开发除外）。缓存覆盖应用入口、使用过的构建资源与字体，AI、RSS、搜索、监控等在线功能仍需要网络。新版本下载完成后会提示刷新，由用户决定何时更新。

## 浏览器书签扩展

配套的「搭搭书签桥」是 Chrome / Edge 的 Manifest V3 扩展，用于读取、整理浏览器书签，以及在浏览器书签栏的「搭搭」文件夹中添加书签。扩展仅在用户手动启用的网站上工作。

`pnpm pack:ext` 会生成 `public/dada-bookmarks-extension.zip`，`pnpm build` 也会自动打包。当前可在浏览器扩展管理页开启开发者模式，加载已解压的 `extension/` 目录，再在搭搭站点启用扩展。

详细步骤见 [扩展说明](extension/README.md)。[应用商店上架材料](docs/extension-store-listing.md) 已包含介绍、权限用途和隐私说明；商店截图与安装地址仍需补齐。

## 项目结构与扩展

| 路径 | 职责 |
| --- | --- |
| `src/App.tsx`、`src/components/` | 应用外壳、页面渲染、设置、对话和其他界面 |
| `src/widgets/` | 内置组件及其注册入口 |
| `src/lib/workspace.ts`、`workspaceStore.ts`、`ops.ts` | 工作空间模型、迁移、状态、编辑操作与撤销重做 |
| `src/lib/registry.ts` | 组件协议、配置描述与校验 |
| `src/lib/applications.ts` | AI 应用目录、分组、打开方式、入口、设置与页面挂载操作 |
| `src/lib/ai.ts`、`tools.ts`、`siteTools.ts`、`lifeTools.ts`、`searchTools.ts` | AI 会话、工具调用与站内操作 |
| `src/lib/applet/`、`src/fx/` | 小程序沙盒与渲染、特效素材库 |
| `src/lib/db.ts`、`storage.ts`、`sync.ts` | IndexedDB、备份与跨设备同步 |
| `extension/`、`worker/`、`server/`、`docker/` | 浏览器扩展、独立 Worker、内置取数代理与容器配置 |
| `tests/content-regressions.html`、`server/*.test.mjs` | 浏览器内容解析回归、生产代理自动测试 |

扩展时遵循以下约定：

1. **统一界面与主题变量**：控件优先使用 Lobe UI，颜色、字体和表面样式遵循主题变量；布局、状态与无障碍要求见 [设计规范](docs/design-system.md)。
2. **通过协议注册组件**：组件声明类型、名称、配置描述、默认值、渲染入口和可选设置界面，使页面系统与 AI 能发现和使用。新增内置组件时，在 `src/widgets/` 实现并注册，在 `src/lib/workspace.ts` 中补充类型，并加入 `src/widgets/index.ts`。
3. **结构与业务数据分开保存**：页面中的组件实例、顺序和配置可 JSON 序列化；组件业务数据使用独立命名空间，主题和模板可以复用设计而不携带业务数据。
4. **通过工具修改工作空间**：AI 编辑走参数校验与工作空间操作，遵循撤销历史和权限规则；自定义交互工具优先采用 Applet，需要完整自定义视觉时使用沙盒应用。

## 品牌

**搭搭**是图来设计（tulai.design）的 AI 个人主页搭建助手。名字亲切、好记，也表达了“陪你一起搭起来”的感觉。它和图来设计旗下的 **齐默默** 一样，希望把复杂能力变成日常、顺手、真正帮得上忙的工具。
